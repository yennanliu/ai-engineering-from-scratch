# 紅隊演練：PAIR 與自動化攻擊

> Chao、Robey、Dobriban、Hassani、Pappas、Wong（NeurIPS 2023，arXiv:2310.08419）。PAIR —— Prompt Automatic Iterative Refinement（提示詞自動迭代精煉）—— 是那套經典的自動化黑箱越獄。一個帶紅隊系統提示詞的攻擊者 LLM，對著目標 LLM 反覆提出越獄嘗試，並把歷次嘗試與回應累積在自己的對話歷史裡當作脈絡內回饋。PAIR 通常在 20 次查詢之內就成功，比 GCG（Zou 等人的詞元層級梯度搜尋）有效率好幾個數量級，而且不需要白箱存取。PAIR 如今是 JailbreakBench（arXiv:2404.01318）與 HarmBench 裡的標準基線，與 GCG、AutoDAN、TAP，以及具說服力的對抗提示詞並列。

**類型：** 實作

**先修單元：** 階段 18 · 01（指令遵循）、階段 14（代理工程）

## 學習目標

- 描述 PAIR 演算法：攻擊者系統提示詞、迭代精煉、脈絡內回饋。
- 解釋當目標是黑箱時，PAIR 為何嚴格比 GCG 更有效率。
- 說出另外四種自動化攻擊基線（GCG、AutoDAN、TAP、PAP），並說出各自的一項區別特徵。
- 描述 JailbreakBench 與 HarmBench 的評估協定，以及在各自之下「攻擊成功率」是什麼意思。

## 問題所在

紅隊演練以前是一項手工活動。少數專家測試者建構對抗提示詞，並追蹤哪些管用。這不擴縮：攻擊成功率需要統計樣本，而每次模型發布，目標都在移動。PAIR 把紅隊演練操作化成一個「目標為黑箱」的最佳化問題。

## 核心概念

### PAIR 演算法

輸入：
- 目標 LLM T（我們正在攻擊的模型）。
- 裁判 LLM J（替一份回應是不是越獄打分）。
- 攻擊者 LLM A（那個紅隊最佳化器）。
- 目標字串 G：「用〔有害指示〕回應。」
- 預算 K（通常 20 次查詢）。

迴圈，k 從 1 到 K：
1. 用目標 G 以及目前為止的（提示詞, 回應）配對歷史去提示 A。
2. A 吐出一段新的提示詞 p_k。
3. 把 p_k 送給 T；收到回應 r_k。
4. J 依目標替 (p_k, r_k) 打分。
5. 若分數 >= 門檻，就停 —— 找到越獄了。
6. 否則，把 (p_k, r_k) 附到 A 的歷史裡；繼續。

實證結果（NeurIPS 2023）：對 GPT-3.5-turbo、Llama-2-7B-chat 的攻擊成功率 >50%；成功所需的平均查詢次數落在 10-20 之間。

### 為什麼 PAIR 有效率

GCG（Zou 等人 2023）用梯度在對抗性詞元後綴上做搜尋；它需要白箱模型存取，而且產出的是讀不懂的後綴。PAIR 是黑箱的，產出的是能跨模型遷移的自然語言攻擊。PAIR 的脈絡內回饋讓攻擊者從每一次被拒中學習；GCG 沒有對應物（每一次新的詞元更新都得把先前的進展重新發現一遍）。

### 相關的自動化攻擊

- **GCG（Zou 等人 2023，arXiv:2307.15043）。** 對抗後綴的詞元層級梯度搜尋。白箱、可遷移，產出讀不懂的字串。
- **AutoDAN（Liu 等人 2023）。** 在提示詞上做演化式搜尋，由一個階層式目標函式引導。
- **TAP（Mehrotra 等人 2024）。** 帶剪枝的攻擊樹 —— 分支出多條 PAIR 風格的推演。
- **PAP（Zeng 等人 2024）。** 具說服力的對抗提示詞 —— 把人類的說服技巧編碼成提示詞樣板。

### JailbreakBench 與 HarmBench

兩者（2024）都把評估標準化：

- JailbreakBench（arXiv:2404.01318）。橫跨 10 個 OpenAI 政策類別的 100 種有害行為。以攻擊成功率（ASR）為主要指標。需要一位裁判（GPT-4-turbo、Llama Guard，或 StrongREJECT）。
- HarmBench（Mazeika 等人 2024）。橫跨 7 個類別的 510 種行為，含語意與功能性的傷害測試。拿 18 種攻擊對上 33 個模型做比較。

ASR 通常在固定的查詢預算下回報。比較攻擊時必須把預算對齊；「200 次查詢下 90% ASR」與「20 次查詢下 85% ASR」不能相提並論。

### 這對 2026 年的部署為什麼要緊

現在每家前沿實驗室在發布前，都會對生產模型跑 PAIR 與 TAP。ASR 的軌跡會出現在模型卡（第 26 課）與安全論證附錄（第 18 課）裡。這種攻擊並不奇特 —— 它是標準基礎設施。

## 框架應用

`code/main.py` 建出一個玩具型的 PAIR 迴圈。目標是一個會拒絕「明顯」有害提示詞的模擬分類器（關鍵字過濾器）。攻擊者是一個以規則為基礎的精煉器，會嘗試改寫、角色扮演框架與編碼。裁判替回應打分。你會看到攻擊者在約 5-15 次迭代內攻破關鍵字過濾器，並在語意過濾器上失敗。

## 產出交付

這一課產出 `outputs/skill-attack-audit.md`。給定一份紅隊評估報告，它會稽核：跑了哪些攻擊（PAIR、GCG、TAP、AutoDAN、PAP）、各自用了多少預算、用了哪位裁判、在哪一組有害行為集上（JailbreakBench、HarmBench、內部自建）。

## 練習

1. 跑 `code/main.py`。量測三種內建攻擊者策略的「平均成功所需查詢次數」。解釋各自利用的是目標防禦的哪一項假設。

2. 實作第四種攻擊者策略（例如翻成另一種語言、base64 編碼）。回報它對關鍵字過濾器目標與語意過濾器目標的新平均成功查詢次數。

3. 讀 Chao 等人 2023 年的圖 5（PAIR 與 GCG 的比較）。描述兩種即使 PAIR 有效率優勢、仍會偏好 GCG 的情境。

4. JailbreakBench 是對一組固定目標集回報 ASR。設計一項額外指標，量測攻擊的多樣性（成功提示詞之間的變異）。解釋多樣性為何對防禦評估要緊。

5. TAP（Mehrotra 2024）用分支 + 剪枝擴充了 PAIR。替 `code/main.py` 勾勒一個 TAP 風格的擴充，並描述運算成本與成功率之間的取捨。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|-----------------|------------------------|
| PAIR | 「自動化越獄」 | 提示詞自動迭代精煉；攻擊者 LLM + 裁判 LLM 的迴圈 |
| GCG | 「梯度越獄」 | 對抗後綴的白箱詞元層級梯度搜尋 |
| 攻擊成功率（ASR） | 「k 次查詢下的越獄百分比」 | 主要指標；必須連同查詢預算與裁判身分一起回報 |
| 裁判 LLM | 「那個評分者」 | 評判一份回應是否滿足有害目標的 LLM |
| JailbreakBench | 「那份評估」 | 帶類別標記的標準化有害行為集 |
| HarmBench | 「那份更廣的基準」 | 510 種行為，含功能性 + 語意的傷害測試 |
| TAP | 「攻擊樹」 | 帶分支 + 剪枝的 PAIR；運算更高、ASR 更好 |
