# 為什麼要用 Transformer —— RNN 的問題所在

> RNN 一次處理一個詞元。Transformer 一次處理所有詞元。這一個架構上的賭注，改寫了 2017 年之後深度學習的每一條擴展曲線。

**類型：** 學習
**程式語言：** Python
**先修單元：** 階段 3（深度學習核心）、階段 5 · 09（序列到序列）、階段 5 · 10（注意力機制）
**時間：** 約 45 分鐘

## 問題所在

2017 年之前，地球上每一個最先進的序列模型 —— 語言、翻譯、語音 —— 都是遞迴神經網路。LSTM 與 GRU 在翻譯基準上稱霸了五年，那是相當於 ImageNet 地位的競技場。它們是當時唯一能用的工具。

它們有三個致命弱點。序列式計算意味著你無法沿著時間軸平行化：詞元 `t+1` 需要詞元 `t` 的隱藏狀態。一段 1,024 個詞元的序列，就是在一張每個週期能做 1,000,000 次浮點運算的 GPU 上，跑 1,024 個串列步驟。在一台為平行化而設計的硬體上，訓練的實際耗時卻隨序列長度線性成長。

梯度消失意味著 50 個詞元之前的資訊，早已被壓過 50 層非線性。閘控遞迴單元（LSTM、GRU）緩和了這種壓縮，卻從未真正消除它。長距離依賴 ——「我去年夏天在飛往京都的飛機上讀的那本書……」—— 經常整個失效。

固定寬度的隱藏狀態意味著編碼器要在解碼器看到任何東西之前，把整段來源序列擠進單一向量。來源是 5 個詞元或 500 個詞元都無所謂，這個瓶頸的形狀始終一樣。

2017 年的論文〈Attention Is All You Need〉提出了一個激進的做法：徹底丟掉遞迴。讓每個位置平行地注意所有其他位置。用一次大矩陣乘法取代 1,024 次序列運算。

到了 2026 年，這個結果稱霸每一種模態。語言（GPT-5、Claude 4、Llama 4）、視覺（ViT、DINOv2、SAM 3）、音訊（Whisper）、生物（AlphaFold 3）、機器人（RT-2）。同一個區塊，不同的輸入。

## 核心概念

![RNN 的序列式計算與 Transformer 的平行注意力對照](../assets/rnn-vs-transformer.svg)

**遞迴就是瓶頸。** RNN 計算 `h_t = f(h_{t-1}, x_t)`。每一步都依賴前一步。你沒辦法在 `h_4` 之前算出 `h_5`。在擁有一萬個以上平行核心的現代 GPU 上，處理長序列時這會浪費掉 99% 的矽。

**注意力就是廣播。** 自注意力對每一組 `(i, j)` 同時計算 `output_i = sum_j(a_ij * v_j)`。整個 N×N 的注意力矩陣在一次批次矩陣乘法中填滿。沒有哪一步依賴另一步。GPU 最愛這種。

**加速幅度不是一個常數。** 它是 `O(N)` 串列深度與 `O(1)` 串列深度之間的差別。實務上，在同等硬體、N=512 的條件下，Transformer 每個 epoch 的訓練速度快 5 到 10 倍，而且這個差距會隨序列長度持續拉開，直到你撞上注意力的 `O(N²)` 記憶體牆（後來 Flash Attention 解決了它 —— 見單元 12）。

**Transformer 的代價。** 注意力的記憶體以 `O(N²)` 成長。2K 脈絡沒問題；128K 脈絡就得靠滑動視窗、RoPE 外推、Flash Attention 分塊，或線性注意力的變體。遞迴在時間與記憶體上都是 `O(N)`；Transformer 拿記憶體換時間，再靠平行化把時間賺回來。

**歸納偏差的轉移。** RNN 假設局部性與近期性。Transformer 什麼都不假設 —— 每一組配對都是注意力的候選。這正是為什麼 Transformer 需要更多資料才能訓得好，但一旦有了資料就能擴展得更遠。Chinchilla（2022）把這件事形式化了：只要詞元足夠多，Transformer 永遠勝過同等參數量的 RNN。

## 動手實作

這裡沒有神經網路 —— 我們用數值方式模擬核心瓶頸，讓你在自己的筆電上感受到那道落差。

### 步驟 1：量測串列深度

請看 `code/main.py`。我們建兩個函式。一個把序列編碼成一連串加法（串列，像 RNN）。另一個把它編碼成平行歸約（廣播，像注意力）。同樣的數學，不同的依賴圖。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # can't parallelize: h depends on previous h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # every x is independent
```

我們對長達 100,000 個元素的序列分別計時。RNN 版本是 O(N)，而且只用單一 CPU 管線。就算在純 Python 裡，長度大於等於 1,000 時注意力風格的歸約也會勝出，因為 Python 的 `sum()` 是用 C 實作的，逐項迭代時不必為每一步付出解譯器開銷。

### 步驟 2：計算理論運算次數

兩個演算法都做 N 次加法。差別在*依賴深度*：在下一個運算能開始之前，有多少運算必須依序完成。RNN 深度 = N。注意力深度用樹狀歸約是 log(N)，用平行掃描則是 1。決定 GPU 時間的是深度，不是運算次數。

### 步驟 3：長序列上的實測擴展

我們會印出一張計時表，把 O(N) 的落差呈現出來。在 2026 年的 Mac 筆電上，長度低於 1,000 的序列快到量不出來。長度 100,000 的序列則顯示出乾淨的線性掃描。把這個規模放大到一個 16,384 詞元的 Transformer 與等價的 12 層 LSTM，你就能明白 2016 年為什麼訓練的實際耗時是個攔路虎。

## 框架應用

2026 年還會選 RNN 的場合：

| 情境 | 選擇 |
|-----------|------|
| 串流推論、一次一個詞元、記憶體固定 | RNN 或狀態空間模型（Mamba、RWKV） |
| 極長序列（超過 100 萬詞元），注意力記憶體會爆掉 | 線性注意力、Mamba 2、Hyena |
| 沒有矩陣乘法加速器的邊緣裝置 | 深度可分離 RNN 在每瓦 FLOP 上仍然勝出 |
| 其他任何情況（訓練、批次推論、脈絡最多 128K） | Transformer |

像 Mamba 這樣的狀態空間模型（SSM）本質上就是 RNN，只是有結構化的參數化，讓它兼得兩者之長：`O(N)` 的掃描記憶體，加上經由選擇性掃描達成的平行訓練。它們能拿回 Transformer 九成的品質，而長脈絡的擴展性更好。2026 年多數前沿實驗室訓練的是 SSM 與 Transformer 的混合模型（例如 Jamba、Samba）—— 遞迴沒有死，它成了一個元件。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|-----------------------|
| 遞迴 | 「RNN 是序列式的」 | 第 `t` 步依賴第 `t-1` 步的計算方式，迫使執行沿時間軸串列進行。 |
| 串列深度 | 「圖有多深」 | 相依運算的最長鏈；即使硬體無限，它也框住了實際耗時。 |
| 注意力 | 「讓詞元互看彼此」 | 加權和 `sum_j a_ij v_j`，其中 `a_ij` 來自位置 i 與 j 之間的相似度分數。 |
| 脈絡視窗 | 「模型看得到多少」 | 一層注意力能吃進多少個位置；二次成長的記憶體成本就是隨這個數字放大。 |
| 歸納偏差 | 「架構裡內建的假設」 | 對資料長相的先驗；CNN 假設平移不變性，RNN 假設近期性。 |
| 狀態空間模型 | 「有代數撐著的 RNN」 | 經過參數化的遞迴，可透過結構化狀態空間矩陣做平行訓練。 |
| 二次瓶頸 | 「為什麼脈絡這麼貴」 | 注意力記憶體在序列長度上是 `O(N²)`；Flash Attention 藏起了常數，藏不了這個成長階數。 |
