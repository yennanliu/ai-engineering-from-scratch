# 文件與圖表理解

> 文件不是照片。一份 PDF、一篇科學論文、一張發票或一份手寫表單，都帶有版面、表格、圖表、註腳、頁首與語意結構，而這些是純影像理解捕捉不到的。VLM 之前的那套堆疊是條管線：Tesseract OCR + LayoutLMv3 + 表格抽取的啟發式規則。VLM 這波浪潮用免 OCR 的模型取代了它 —— Donut（2022）、Nougat（2023）、DocLLM（2023）—— 它們直接吐出結構化標記。到了 2026 年，前沿就只剩「把頁面影像以 2576px 原生解析度餵給 Claude Opus 4.7」，而結構化標記的輸出是附贈的。這一課會讀文件 AI 這三個世代的弧線。

**類型：** 實作
**程式語言：** Python (stdlib, layout-aware document parser skeleton)
**先修單元：** 階段 12 · 05（LLaVA）、階段 5（NLP）
**時間：** 約 180 分鐘

## 學習目標

- 說明文件 AI 的三個世代：OCR 管線、免 OCR、VLM 原生。
- 描述 LayoutLMv3 的三條輸入串流：文字、版面（bbox）、影像 patch，以及統一的遮罩方式。
- 比較 Donut（免 OCR，影像 → 標記）、Nougat（科學論文 → LaTeX）、DocLLM（版面感知的生成式）、PaliGemma 2（VLM 原生）。
- 為一項新任務挑一個文件模型（發票、科學論文、手寫表單、中文收據）。

## 問題所在

「看懂這份 PDF」難得有點騙人。資訊藏在：

- 文字內容（訊號的 90%）。
- 版面（頁首、註腳、側欄、雙欄格式）。
- 表格（列、行、合併儲存格）。
- 圖與圖表。
- 手寫註記。
- 字型與排版（標題對內文）。

原始 OCR 把文字倒出來，其餘全丟。一個在乎發票的系統，得知道「總計：$1,245」是來自右下角，而不是來自某個註腳。

## 核心概念

### 第 1 世代 —— OCR 管線（2021 年之前）

那套經典堆疊：

1. PDF → 每頁一張影像。
2. Tesseract（或商用 OCR）抽出文字並附上每個字的邊界框。
3. 版面分析器辨識出區塊（頁首、表格、段落）。
4. 表格結構辨識器解析表格。
5. 領域規則 + 正規表示式抽出欄位。

對乾淨的印刷文字有效。碰到手寫、歪斜的掃描、複雜表格、非英文字體就崩了。每一種失敗模式都需要一條客製的例外路徑。

### TrOCR（2021）

TrOCR（Li 等人，arXiv:2109.10282）把 Tesseract 那套經典的 CNN-CTC，換成一個在合成 + 真實文字影像上訓練的 Transformer 編碼器—解碼器。在手寫與多語言文字上乾淨勝出。它仍然是條管線（先偵測、再 TrOCR、再版面），但 OCR 那一步大幅進步了。

### 第 2 世代 —— 免 OCR（2022 到 2023）

第一批免 OCR 的模型說：徹底跳過偵測，直接把影像像素映射到結構化輸出。

Donut（Kim 等人，arXiv:2111.15664）：
- 編碼器—解碼器 Transformer，編碼器是 Swin-B。
- 輸出是表單理解用的 JSON、摘要用的 markdown，或任何任務專屬的 schema。
- 沒有 OCR、沒有版面、沒有偵測。

Nougat（Blecher 等人，arXiv:2308.13418）：
- 專門在科學論文上訓練。
- 輸出是 LaTeX／markdown。
- 能處理方程式、多欄版面與圖。
- 每個 arXiv 解析器都會呼叫的那個模型。

這些是專才，不是通才。Donut 碰到科學論文就失敗；Nougat 碰到發票也失敗。

### LayoutLMv3（2022）

另一條路線。LayoutLMv3（Huang 等人，arXiv:2204.08387）保留了 OCR，但加上了版面理解：

- 三條輸入串流：OCR 文字詞元、每個詞元的二維邊界框、影像 patch。
- 橫跨全部三種模態的遮罩訓練目標（遮文字、遮 patch、遮版面）。
- 下游任務：分類、實體抽取、表格問答。

LayoutLMv3 是基於 OCR 的文件理解的巔峰。在表單與發票上很強。上游需要 OCR。在標準化的文件基準上，這是 VLM 之前最好的準確率。

### DocLLM（2023）

DocLLM（Wang 等人，arXiv:2401.00908）是 LayoutLM 的生成式手足。它以版面詞元為條件生成自由形式的答案。做文件問答更好；但仍依賴 OCR 輸入。

### 第 3 世代 —— VLM 原生（2024 起）

2024 年的 VLM 已經好到足以徹底取代那條管線。把整頁影像以高解析度餵給 VLM，提問，拿到答案。

- LLaVA-NeXT 的 336 鋪排 AnyRes 對小份文件有效。
- Qwen2.5-VL 的動態解析度原生就能處理 2048 以上的像素。
- Claude Opus 4.7 支援 2576px 的文件。
- PaliGemma 2（2025 年 4 月）專門為文件 + 手寫訓練。

VLM 原生與 OCR 管線之間的落差迅速收攏。到了 2026 年，VLM 原生在這些方面勝出：

- 場景文字（手寫 + 印刷、多種字體混雜）。
- 帶合併儲存格的複雜表格。
- 嵌在文字裡的數學方程式。
- 帶文字註記的圖。

OCR 管線仍然在這些方面勝出：

- 大規模的純掃描工作負載，且每頁延遲很要緊。
- 管線的可靠性（確定性的失敗，相對於 VLM 的幻覺）。
- 需要可稽核 OCR 輸出的受監管環境。

### Claude 4.7／GPT-5 的前沿

在 2576 像素的原生輸入下，前沿 VLM 的文件理解已接近人類準確率。2026 年初的基準數字：

- DocVQA：Claude 4.7 約 95.1，PaliGemma 2 約 88.4，Nougat 約 77.3，管線式 LayoutLMv3 約 83。
- ChartQA：Claude 4.7 約 92.2，GPT-4V 約 78。
- VisualMRC：Claude 4.7 約 94。

封閉模型的領先，主要來自解析度與基礎 LLM 的規模。7B 的開放模型落後幾分，但正在追上。

### 數學方程式與 LaTeX 輸出

科學論文需要方程式的精確 LaTeX 輸出。Nougat 就是為此訓練的。以 LaTeX 為目標訓練的 VLM（Qwen2.5-VL-Math、Nougat 的衍生模型）能產出可用的 LaTeX。缺乏明確的 LaTeX 訓練，VLM 產出的轉錄讀得懂但不精確。

2026 年做科學論文管線：先在 PDF 上串 Nougat，難搞的頁面再交給 VLM。

### 手寫

仍是最難的子任務。印刷與手寫混雜（醫師處方、填好的表單）正是 OCR 管線在成本上仍勝過 VLM 的地方。純手寫的 VLM 正在進步（Claude 4.7、PaliGemma 2）。

### 2026 年的配方

要做一個新的文件 AI 專案：

- 大規模的純印刷發票：LayoutLMv3 + 規則，成本效益高。
- 混合文件（科學 + 手寫 + 表單）：VLM 原生（PaliGemma 2 或 Qwen2.5-VL）。
- 完整的 arXiv 匯入：數學交給 Nougat，圖交給 VLM。
- 受監管場景：OCR 管線 + VLM 驗證器做交叉核對。

## 框架應用

`code/main.py`：

- 一個玩具版的版面感知分詞器：給定 (文字, bbox) 配對，產出 LayoutLMv3 風格的輸入。
- 一個 Donut 風格的任務 schema 產生器：表單用的 JSON 模板。
- 一份跨 OCR 管線、Donut、Nougat 與 VLM 原生的每頁詞元預算比較。

## 產出交付

這一課產出 `outputs/skill-document-ai-stack-picker.md`。給定一個文件 AI 專案（領域、規模、品質、法規），它會在 OCR 管線、免 OCR 專才與 VLM 原生之間做出選擇。

## 練習

1. 你的專案是每天 1000 萬張發票。哪套堆疊能在不犧牲準確率的前提下，把每頁成本壓到最低？

2. 為什麼 LayoutLMv3 在表單問答上勝過純 CLIP 式的 VLM，卻在場景文字上落後？那條 bbox 串流放棄了什麼？

3. Nougat 生成 LaTeX。提出一個 VLM 原生輸出在 LaTeX 保真度上勝過 Nougat 的測試案例，以及一個 Nougat 勝出的案例。

4. 讀 PaliGemma 2 論文（Google，2024）。相對於 PaliGemma 1，讓文件準確率提升的關鍵訓練資料增補是什麼？

5. 設計一套法規上安全的混合方案：OCR 管線為主，VLM 為輔做交叉核對。兩者不一致時你要怎麼裁決？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| OCR 管線 | 「Tesseract 式」 | 分階段的堆疊：偵測 -> OCR -> 版面 -> 規則；確定性，但脆弱 |
| 免 OCR | 「Donut 式」 | 跳過明確 OCR 的影像轉輸出 Transformer；單一模型 |
| 版面感知 | 「LayoutLM」 | 輸入包含每個詞元的 bbox 座標；跨模態的統一遮罩 |
| VLM 原生 | 「前沿 VLM」 | 把頁面影像以高解析度直接餵給 Claude／GPT／Qwen 的 VLM；沒有管線 |
| DocVQA | 「文件基準」 | 文件 VQA 的標準；被引用最多的分數 |
| 標記輸出 | 「LaTeX／MD」 | 結構化的輸出格式而非自由形式文字；讓下游自動化成為可能 |
