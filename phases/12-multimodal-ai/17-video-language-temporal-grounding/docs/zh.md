# 影片—語言模型：時間詞元與接地

> 影片不是一疊照片。一段 5 秒的片段有因果順序、動作動詞與事件時序，而這些是影像模型表徵不出來的。Video-LLaMA（Zhang 等人，2023 年 6 月）出貨了第一個帶視聽接地的開放影片 LLM。VideoChat 與 Video-LLaVA 把這套模式擴大。到了 2025 年，Qwen2.5-VL 的 TMRoPE 補上了與前沿專有模型之間的落差。每一套系統解決時間詞元的方式都不同 —— 逐片段的 Q-former、逐畫格的 concat-pool、逐詞元的 TMRoPE。這一課會讀這些模式，做一個均勻對動態的畫格取樣器，並在時間接地任務上做評測。

**類型：** 實作
**程式語言：** Python (stdlib, frame sampler + temporal-grounding evaluator)
**先修單元：** 階段 12 · 08（LLaVA-OneVision）
**時間：** 約 180 分鐘

## 學習目標

- 說明為什麼時間位置編碼會獨立於視覺編碼器之外，改變影片 VLM 的表現。
- 在每秒詞元數與接地準確率上，比較均勻、動態 FPS 與事件驅動三種畫格取樣。
- 描述逐片段 Q-former（Video-LLaMA）、逐畫格池化（Video-LLaVA）與逐詞元 M-RoPE（Qwen2.5-VL）三種設計。
- 說出四項影片基準：VideoMME、TempCompass、EgoSchema、Video-MMMU。

## 問題所在

一段 1 分鐘、30 FPS 的影片是 1800 個畫格。每畫格 196 個視覺詞元（224 解析度的 ViT-B）算下來就是 35.2 萬個詞元 —— 比 2024 年代任何 LLM 的脈絡都大。

有三種縮減策略：

1. 對畫格做次取樣（依內容取 1 到 8 FPS）。
2. 積極地對每個畫格的 patch 詞元做池化（3x3 或 4x4 的雙線性池化）。
3. 用一個 Q-former 壓縮，吃進一段 16 畫格的片段、吐出 64 個詞元。

三者的取捨各不相同。次取樣流失時間細節。池化流失空間細節。Q-former 兩者都流失一點，但省下詞元。

時間位置編碼是另一根軸：模型怎麼知道畫格 5 排在畫格 6 之前？選項包括簡單的一維時間 RoPE（Video-LLaMA）、學習得來的時間嵌入（Video-LLaVA），以及 TMRoPE（Qwen2.5-VL，完整三維）。

## 核心概念

### Video-LLaMA：逐片段 Q-former + 音訊分支

Video-LLaMA（2023）是第一個開放的影片 LLM。架構是：

- 以 2 FPS 取樣的 16 畫格片段（也就是 8 秒）。
- 逐畫格的 ViT 特徵 -> 一個對全部 16 個畫格做交叉注意力的 Video Q-former -> 32 個學習得來的 query -> LLM。
- 平行的音訊分支：波形 -> ImageBind 音訊編碼器 -> Audio Q-former -> 32 個 query -> LLM。

強項：視聽聯合推理。弱點：片段長度固定，無法做任意時間點的接地。

### VideoChat 與 Video-LLaVA

VideoChat 保留了 Video-LLaMA 的想法，但拿掉音訊並加以簡化。Video-LLaVA（Lin 等人，2023）則用單一個視覺編碼器同時在影像與影片畫格上訓練（「投影之前先對齊」），得到一份統一的表徵。兩者都是「凍結的 CLIP 編碼器 + MLP + LLM」。

兩者都處理不了長影片。都是 8 到 16 畫格的系統。

### Qwen2.5-VL 與 TMRoPE

Qwen2.5-VL 引入了 TMRoPE —— 時間—模態旋轉位置嵌入。每個 patch 詞元都帶一個 (t, h, w) 位置，其中 t 是實際的時間戳（不是畫格索引）。

它與簡單時間嵌入的關鍵差異：

- 是絕對時間，不是索引。模型看到的是「在第 4.2 秒」，而不是「在第 15 個畫格」。
- 是逐詞元旋轉，不是逐片段。每個視覺詞元依自己的時間戳獨立旋轉。
- 與動態 FPS 相容。就算你這裡用 2 FPS、那裡用 4 FPS 取樣，TMRoPE 原生就能處理這種不均勻的間距。

TMRoPE 讓「貓在第幾秒跳起來？」這類查詢成為可能。模型能輸出「在第 4.2 秒」。Video-LLaMA 就只能說「在片段的前段」。

### 畫格取樣策略

均勻：在整段時長上均勻取 N 個畫格。簡單，但會錯過動作高峰。

動態 FPS：依動態強度自適應取樣。用光流或畫格差分挑出高動態的區段，在那裡取得更密。Qwen2.5-VL 就是在這上面訓練的。

事件驅動：跑一個輕量偵測器，在有動作發生的地方多取一些。VideoAgent 用的就是這招。

關鍵畫格 + 脈絡：在鏡頭邊界處取樣，再加上鄰近的幾個畫格。用於電影類內容。

### 逐畫格池化

在 1 FPS、每畫格 576 個詞元之下，一段 5 分鐘的片段是 172,800 個詞元。用 Qwen2.5-VL-72B 的 128k 脈絡撐得住，但很貴。

3x3 的雙線性池化縮到每畫格 64 個詞元 -> 5 分鐘 19,200 個詞元。這是多數任務的甜蜜點。

對空間細節沒那麼要緊的代理程式工作流程，可以池化得更積極（6x6 -> 每畫格 16 個詞元）。

### 四項影片基準

- VideoMME：全面的影片理解，涵蓋短、中、長。
- TempCompass：細粒度的時間推理，「之前」／「之後」類的問題。
- EgoSchema：長時程的第一人稱影片。
- Video-MMMU：多模態、跨學科的影片問題。

一次完整的影片 VLM 評測會把四項都跑過。它們施壓的軸不同 —— TempCompass 全是關於順序，EgoSchema 是關於 3 分鐘以上的推理，VideoMME 則橫跨各種時長。

### 接地的輸出格式

時間接地的輸出格式有：

- 自由文字：「貓在大約 4 秒的地方跳起來。」好解析但不精確。
- 結構化 JSON：`{"event": "jump", "start": 4.1, "end": 4.3}`。Qwen2.5-VL 訓練的就是這個。
- 詞元式：與答案交錯的特殊 `<time>4.1</time>` 詞元。這是 Qwen2.5-VL 的內部格式。

就下游用途而言，詞元式最準確。而 Qwen2.5-VL 的 JSON 輸出格式可以直接解析。

### 2026 年的最佳實務

2026 年做影片 VLM：

- 編碼器：搭配 M-RoPE 或 TMRoPE 的 SigLIP 2（Qwen2.5-VL）。
- 畫格取樣：動態 FPS（依動態量取 1 到 4），並設最大畫格數上限。
- 逐畫格池化：3x3 雙線性。
- 輸出：帶時間與事件欄位的結構化 JSON。
- 基準：一般用途用 VideoMME + TempCompass；長時程用 EgoSchema。

## 框架應用

`code/main.py` 包含：

- 均勻與動態 FPS 兩種畫格取樣器。
- 一個玩具版的時間接地評測器：給定時間 T 上的一個「標準答案」事件與一段模型輸出，在容許誤差之下為準確率評分。
- 一份橫跨 Video-LLaMA（16 畫格、Q-former）、Video-LLaVA（8 畫格、MLP）、Qwen2.5-VL（動態 FPS + TMRoPE）的比較。

## 產出交付

這一課產出 `outputs/skill-video-vlm-frame-planner.md`。給定一項影片任務（監控、動作辨識、時間接地、摘要），它會挑出畫格取樣器、池化係數、輸出格式與預期的準確率級距。

## 練習

1. 對一段 3 分鐘的烹飪示範，在均勻與動態 FPS 之間做選擇。用詞元數為你的選擇辯護。

2. TMRoPE 具體多做到了什麼，是簡單的時間嵌入表辦不到的？

3. 為時間接地寫一份 VLM 學得會吐出來的 JSON schema。要涵蓋錯誤情境。

4. 讀 Video-LLaVA 第 3 節的「投影之前先對齊」。這為什麼比分別訓練影像與影片編碼器更好？

5. 看 VideoMME 排行榜，截至 2026 年，最強的開放模型與最強的專有模型之間差距多大？這道落差有多少能歸因於時間編碼、多少歸因於基礎 LLM 的規模？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| 時間接地 | 「有時間定位的答案」 | VLM 針對某個事件何時發生，輸出一段具體的時間戳範圍 |
| TMRoPE | 「時間—多模態 RoPE」 | 帶絕對時間戳的三維旋轉位置，Qwen2.5-VL 所使用 |
| 動態 FPS | 「感知動態的取樣」 | 在高動態區段多取畫格，靜態區段少取 |
| 畫格池化 | 「逐畫格的空間壓縮」 | 在進 LLM 之前，用雙線性內插減少每畫格的 patch 數 |
| Video Q-former | 「片段壓縮器」 | 把 N 個畫格映射成 K 個學習得來 query 的交叉注意力瓶頸 |
| VideoMME | 「影片基準」 | 全面涵蓋短／中／長影片的基準，樣本數 2500 以上 |
