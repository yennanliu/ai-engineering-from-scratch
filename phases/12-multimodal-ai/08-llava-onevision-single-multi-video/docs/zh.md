# LLaVA-OneVision：單影像、多影像、影片統統一個模型

> 在 LLaVA-OneVision（Li 等人，2024 年 8 月）之前，開放 VLM 的世界是幾條各自獨立的血脈：做單影像的 LLaVA-1.5、Mantis 與 VILA 這類多影像模型、Video-LLaVA 與 Video-LLaMA 這類影片模型。每一個都拿下自己的基準，卻在別人的基準上摔跤。LLaVA-OneVision 主張：單一課程就能訓出一個在三種情境全面稱霸的模型，而且那些浮現出來的任務遷移效應（單影像技能輸出到影片、多影像推理輸出到單影像）會勝過各路專才的總和。這份配方簡單得有點騙人：一個跨情境維持恆定的視覺詞元預算，加上一套從單影像走到 OneVision（多影像）再走到影片的明確課程。這一課會讀這個預算、這套課程，以及那些浮現出來的行為。

**類型：** 實作
**程式語言：** Python (stdlib, token budget solver + curriculum planner)
**先修單元：** 階段 12 · 05（LLaVA）、階段 12 · 06（任意解析度）
**時間：** 約 180 分鐘

## 學習目標

- 設計一個在單影像、多影像與影片輸入之間維持恆定的視覺詞元預算。
- 排出一套訓練課程，把技能從單影像遷移到影片而不發生災難性遺忘。
- 說明為什麼在課程排對的前提下，同樣參數量的單一模型能勝過各路專才。
- 說出 LLaVA-OneVision 回報的三項浮現能力：多鏡頭推理、set-of-mark 提示，以及 iPhone 截圖代理程式。

## 問題所在

影像、多影像與影片，各自對模型施加的壓力都不一樣。

單影像要的是高解析度詞元（AnyRes，約 2880 個視覺詞元），才抓得到 OCR 與細節。每個樣本的預算：一張影像，2880 個詞元。

多影像要的是好幾張中等解析度的影像（各約 576 個詞元），好讓跨影像的推理塞得進脈絡。每個樣本的預算：4 到 8 張影像，各 576，共 2300 到 4600 個詞元。

影片要的是大量低解析度的畫格（池化後每畫格約 196 個詞元），才捕捉得到時間動態。每個樣本的預算：8 到 32 個畫格，各 196，共 1600 到 6200 個詞元。

如果你訓練多個獨立模型，你就只挑一種預算。如果你訓練單一模型，你需要這個預算能跨情境合理伸縮，而不把脈絡撐爆。

在 OneVision 之前，預設答案是「訓練一種情境，其他不管」。Video-LLaVA 是靠額外的訓練階段，把影片能力硬加到一個影像模型上。LLaVA-NeXT 則用鋪排加上多影像支援。沒有一個能乾淨地同時處理三者。

## 核心概念

### OneVision 的詞元預算

LLaVA-OneVision 挑了一個統一的視覺詞元預算，每個樣本大約 3000 到 4000 個詞元，並依情境做不同配置：

- 單影像：AnyRes-9（3x3 鋪排 + 縮圖），每格在 384 解析度下有 729 個 patch，經 2x2 的積極雙線性池化 → 每格 182 個。總計：9 * 182 + 182 = 1820 個詞元。或者用 AnyRes-4、每格 729 = 2916 + 729。
- 多影像：每張影像用中等解析度（384，不鋪排），729 個詞元且不池化。預算 6 張影像 → 4374 個詞元。
- 影片：32 個畫格在 384 解析度下，經積極的 3x3 雙線性池化 → 每畫格 81 個詞元。總計：32 * 81 = 2592 個詞元。

這樣的配置讓總詞元數大致維持恆定。LLM 永遠不會看到一個把它脈絡撐爆的批次。編碼器在不同情境下產出不同的幾何形狀，但 LLM 吃掉的預算是一樣的。

### 三階段課程

LLaVA-OneVision 分三階段訓練：

1. 單影像 SFT（SI 階段）。全部資料都是單影像加文字。在高解析度的 AnyRes 輸入上訓練。這教會模型感知、OCR 與細粒度理解。用的是 LLaVA-NeXT 的資料，加上 OneVision 專屬的單影像資料。
2. OneVision SFT（OV 階段）。混合單影像 + 多影像 + 影片（畫格均勻取樣）。在統一的詞元預算上訓練。這教會模型應付異質的批次形狀。權重不重設 —— 從 SI 階段接續下來。
3. 任務遷移（TT 階段）。用一份目標任務配方繼續訓練，通常會依產品需求，把多影像或影片的比重加大。這是選配的部署前微調。

關鍵在於：課程的順序有影響。就算用同樣的資料，先訓影片或先訓多影像，影像表現都會比先訓單影像來得差。論文對此有明確的消融實驗。

### 課程為什麼有效

單影像訓練打下感知的底子。patch 詞元承載細粒度的視覺特徵；LLM 學會把它們與文字整合起來。多影像與影片引入的是結構上的挑戰（哪張是哪張、什麼先發生），而這些在缺乏堅實感知底子的情況下很難學會。

如果你把所有情境從零一起訓練，模型會在感知上欠擬合（每個批次的單影像資料有限），又在結構上過度擬合（多影像／影片資料很多）。結果是：一個會照著跨影像推理模式走、但視覺上很淺的模型。

課程的排序，讓你先從 SI 階段拿到感知強度，再從 OV 階段拿到組合式／時序式推理，而兩者都不流失。

### 浮現出來的跨情境技能

LLaVA-OneVision 論文回報了三項浮現能力：

1. 多鏡頭推理。訓練時多影像與影片是分開的；推論時要求它對一個多鏡頭的駕駛場景進行推理。儘管訓練中從未見過那個確切格式，模型仍能正確整合各個視角。
2. Set-of-mark 提示。使用者在影像中用編號標記標註物件；模型就能推理「標記 3 相對於標記 7 在做什麼」。訓練中既沒有標記也沒有標註；這是從空間接地 + 多影像指涉的組合中學來的。
3. iPhone 截圖代理程式。使用者提供一張 iPhone 畫面的截圖，並要求規劃下一次點擊。訓練資料裡有 UI 截圖、使用者工作流程的影片，以及多影像的前後對照配對。它類推到了代理程式這個使用情境。

這些都不是被訓練出來的任務；它們是從課程的組合式結構中浮現出來的。

### 視覺詞元池化

這個詞元預算要求做池化。OneVision 在二維 patch 網格上使用雙線性內插：24x24 = 576 個 patch 變成 12x12 = 144（2 倍係數）或 8x8 = 64（3 倍係數）。池化是在 patch 網格空間做的，不是在詞元空間，這樣才能保留局部性。

每種情境該用多大的池化係數，本身就是一個超參數。池化越少 = 詞元越多 = 表徵越豐富。池化越多 = 詞元越少 = 塞得下越多畫格／影像。

### LLaVA-OneVision-1.5

2025 年的後續版本（LLaVA-OneVision-1.5，arXiv 2509.23661）在訓練資料、模型權重與程式碼上都「完全開放」。它在部分基準上追平了與專有模型的差距，並讓這份配方普及化。同樣的課程，更多的資料，更好的基礎 LLM。架構沒有改變。

### 與 Qwen2.5-VL 的對照

Qwen2.5-VL（見單元 12.09）做了不同的選擇。它用的是 M-RoPE 與動態 FPS，而不是固定池化。它的預算隨輸入伸縮 —— 一段 1 分鐘的影片用掉的詞元比 5 秒的影片多。LLaVA-OneVision 則固定預算、伸縮池化。兩者都行得通；它們是拿可設定性換取可預測性。

## 框架應用

`code/main.py` 是一個 OneVision 風格 VLM 的課程與預算規劃器。給定每個樣本的詞元預算與一份目標情境配方（比方說 40% 單影像、30% 多影像、30% 影片），它會：

- 為每種情境配置解析度、池化係數與畫格數。
- 檢查每種情境都塞得進共享的預算。
- 回報預期的詞元數、LLM 的 FLOPs，以及哪些情境詞元給得不夠。
- 印出一份逐階段的訓練排程。

拿它來規劃一次 OneVision 微調，或替一個 VLM 部署的逐請求成本做健全性檢查。

## 產出交付

這一課產出 `outputs/skill-onevision-budget-planner.md`。給定目標任務分布與每個樣本的預算，它會吐出 AnyRes 係數、每畫格池化、影片畫格數與各課程階段的權重。每當你要訓練或微調一個統一情境的 VLM 時就用它。

## 練習

1. 你的產品有 80% 單影像、10% 多影像（2 到 4 張）、10% 影片（8 到 16 個畫格）。設計那份詞元預算。既然不必做吃重的多影像，省下來的預算你會放到哪裡？

2. 讀 LLaVA-OneVision 第 4.3 節（浮現能力）。提出第四項這套課程很可能解鎖、但論文沒有回報的浮現技能。

3. 把課程順序調換 —— 先訓多影像，再訓單影像，最後訓影片。預測哪些基準會退步，以及為什麼。

4. 論文回報的影片基準，訓練時每個樣本只用了 8 個畫格。這能類推到推論時的 30 秒影片嗎？先崩掉的會是什麼 —— 詞元預算，還是時序推理？

5. 把 24x24 的 patch 雙線性池化到 12x12，每個維度縮小 4 倍。用 stdlib Python 實作這個池化，並驗證每個 2x2 區塊的平均值與雙線性輸出一致。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| OneVision 情境 | 「單影像、多影像或影片」 | 這個統一 VLM 所處理的三種輸入形狀之一；預算在三者之間維持恆定 |
| 詞元預算 | 「每個樣本幾個詞元」 | LLM 在每個訓練／推論樣本中看到的視覺詞元總數，通常是 3000 到 4000 |
| 課程 | 「訓練順序」 | 為了讓遷移能力浮現而選定的階段順序（單影像 → 多影像 → 影片） |
| 雙線性池化 | 「詞元縮水」 | 對（二維的）patch 網格做雙線性內插，在保留局部性的同時減少詞元數 |
| 浮現技能 | 「沒訓練過，卻還是會」 | 因課程的組合結構而在推論時出現、卻沒有對應訓練資料的能力 |
| AnyRes-k | 「k 格設定」 | k 個固定解析度的子鋪排格，加上一張縮圖，典型的 k ∈ {4, 9} |
| 任務遷移 | 「跨情境類推」 | 透過共享骨幹，在單影像上學到的技能能套用到影片上（反之亦然） |
