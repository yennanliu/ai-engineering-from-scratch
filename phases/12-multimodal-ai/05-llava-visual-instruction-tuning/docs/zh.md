# LLaVA 與視覺指令微調

> LLaVA（2023 年 4 月）是這顆星球上被抄襲最多次的多模態架構。它把 BLIP-2 的 Q-Former 換成一個兩層 MLP，把 Flamingo 的帶閘門交叉注意力換成天真的詞元串接，然後用 GPT-4 從純文字字幕生成的 158k 輪視覺指令來訓練。2023 到 2026 年間，任何做過 VLM 的實務工作者，做的都是某種 LLaVA 變體。LLaVA-1.5 加了 AnyRes。LLaVA-NeXT 拉高了解析度。LLaVA-OneVision 用一套配方統一了影像、多影像與影片。這一課會讀這份配方、實作投影器，並解釋為什麼是「比較簡單的那個贏了」。

**類型：** 實作
**程式語言：** Python (stdlib, projector + instruction-template builder)
**先修單元：** 階段 12 · 02（CLIP）、階段 11（LLM 工程 —— 指令微調）
**時間：** 約 180 分鐘

## 學習目標

- 做一個兩層 MLP 投影器，把 ViT patch 嵌入（維度 1024）映射到某個 LLM 的嵌入維度（維度 4096）。
- 走一遍 LLaVA 的兩階段配方：(1) 在 558k 組字幕配對上做投影器對齊，(2) 在 158k 輪 GPT-4 生成的對話上做視覺指令微調。
- 建出一段帶影像詞元佔位符、系統提示詞與 user／assistant 輪次的 LLaVA 格式提示詞。
- 說明為什麼儘管 Q-Former 在詞元預算上佔優，社群還是從 Q-Former 轉向了 MLP。

## 問題所在

BLIP-2 的 Q-Former（見單元 12.03）把一張影像壓成 32 個詞元。乾淨、有效率、跑基準測試很好看。但它有兩個問題。

第一，Q-Former 雖然可訓練，但它的損失不是最終任務。第 1 階段訓練 ITC+ITM+ITG。第 2 階段訓練 LM 損失。那些 query 學到的是某種中介表徵，之後 LLM 還得再把它解碼出來。資訊在瓶頸處流失了。

第二，Q-Former 要 1.88 億參數，而在 LLaVA 那個 2023 年的規模下，你得把它跟你的目標 LLM 一起共同設計。換了 LLM，就要重訓 Q-Former。換了視覺編碼器，也要重訓。每一種組合都是一個獨立的研發專案。

LLaVA 的答案簡單到令人難堪：拿 ViT 的 576 個 patch 詞元，每個都過一個兩層 MLP（`1024 → 4096 → 4096`），然後把全部 576 個倒進 LLM 的輸入序列。沒有瓶頸。沒有第 1 階段那些奇怪目標的預訓練。就只是用一個直接的 LM 損失訓練那個 MLP。

資料從哪來？LLaVA 的第二個洞見：用 GPT-4（純文字版）來生成指令資料。把一張影像的 COCO 字幕與邊界框資料餵給 GPT-4，請它產出對話、描述與複雜推理題。158k 輪指令—回應，免費奉送。不用人工標註。

結果是：一個在 8 張 A100 上跑一天就完成、在 MMMU 上勝過 Flamingo、而且出貨了一個社群可以繼續擴充的開放檢查點的 VLM。到 2023 年底，它已經衍生出 50 個以上的分支。

## 核心概念

### 架構

13B 的 LLaVA-1.5：
- 視覺編碼器：CLIP ViT-L/14 @ 336（第 1 階段凍結，第 2 階段可選擇解凍）。
- 投影器：兩層 MLP 搭配 GELU 激活，`1024 → 4096 → 4096`。
- LLM：Vicuna-13B（後來換成 Llama-3.1-8B）。

在一張影像 + 一段文字提示詞上的前向傳播：

```
img -> ViT -> 576 patches of dim 1024
patches -> MLP -> 576 tokens of dim 4096
prompt: system + "<image>" placeholder + user question
replace <image> token with the 576 projected tokens
feed the full sequence to the LLM
decode response
```

這張影像佔掉 LLM 脈絡的 576 個詞元。在 2048 的脈絡下，只剩 1472 個詞元給文字。在 32k 的脈絡下，這只是個捨入誤差。

### 第 1 階段：投影器對齊

凍結 ViT。凍結 LLM。只訓練那個兩層 MLP。資料集：558k 組影像—字幕配對（LAION-CC-SBU）。損失：以投影後的影像詞元為條件，對字幕做語言建模。

以批次 128 跑單一輪 epoch，幾小時就結束了。投影器學會把 ViT 空間映射到 LLM 空間。沒有任何任務專屬的監督訊號。

### 第 2 階段：視覺指令微調

解凍投影器（仍然可訓練）。解凍 LLM（通常整個解凍，有時用 LoRA）。在 158k 輪視覺指令上訓練。

指令資料才是關鍵把戲。Liu 等人是這樣生成的：
1. 拿一張 COCO 影像。
2. 抽出它的文字描述（5 段人工字幕 + 邊界框清單）。
3. 用三種提示詞模板送給 GPT-4：
   - 對話：「產生一段使用者與助理之間關於這張影像的來回對話。」
   - 詳細描述：「給出一段豐富、細緻的影像描述。」
   - 複雜推理：「問一個需要對這張影像進行推理的問題，然後回答它。」
4. 把 GPT-4 的輸出解析成 (指令, 回應) 配對。

這整套過程完全沒碰到影像本身 —— 只用了文字描述。GPT-4 會幻覺出貌似合理的影像內容。是有些雜訊，但它就是有效：158k 輪就足以解鎖對話能力。

### 社群為什麼抄了這一套

- 沒有第 1 階段專屬的損失要調。從頭到尾都是 LM 損失。
- 投影器幾小時就訓練完，不用好幾天。
- 只要重訓投影器，LLM 就能換掉（LLaVA-Llama2、LLaVA-Mistral、LLaVA-Llama3）。
- 視覺指令的資料管線用的是 GPT-4，要為新領域重新生成一份很便宜。

### LLaVA-1.5 與 LLaVA-NeXT

LLaVA-1.5（2023 年 10 月）加了：
- 把學術任務資料（VQA、OKVQA、RefCOCO）混進指令微調。
- 更好的系統提示詞。
- 脈絡從 2048 拉到 32k。

LLaVA-NeXT（2024 年 1 月）加了：
- AnyRes：把高解析度影像切成 2x2 或 1x3 的 336x336 裁切網格，再加一張全域的低解析度縮圖。每塊裁切變成 576 個詞元；每張影像總共約 2880 個視覺詞元。OCR 與圖表任務的分數大幅跳升。
- 用 ShareGPT4V（高品質的 GPT-4V 字幕）調出更好的指令資料配方。
- 更強的基礎 LLM（Mistral-7B、Yi-34B）。

### LLaVA-OneVision

單元 12.08 會深入談 OneVision。簡短版：同樣的投影器，但用一套課程訓練，讓單影像、多影像與影片在同一個模型裡共享視覺詞元預算。

### 與 Q-Former 的比較

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 每張影像的視覺詞元 | 32 | 576（基礎）或 2880（AnyRes） |
| 可訓練參數 | 1.88 億 + LM | 4000 萬 + LM |
| 第 1 階段損失 | ITC+ITM+ITG | 只有 LM |
| LLM 直接替換 | 需要重訓 | 只要極少的重訓就能換 |
| 多影像 | 彆扭 | 自然（串接） |
| 影片 | 彆扭 | 自然（逐畫格串接） |
| 詞元預算 | 小 | 大 |

MLP 在簡潔性與詞元彈性上勝出。Q-Former 在詞元預算上勝出。到了 2023 年底，詞元預算不再是那道綁手綁腳的限制（LLM 脈絡長到 32k 到 128k 以上），於是簡潔性主導了一切。

### 提示詞格式

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>` 是一個佔位符詞元。在分詞之前，它會被換成那 576 個視覺詞元（用 AnyRes 就是 2880 個）。分詞器看到的序列會比它訓練時見過的略長一些，但 LLM 應付得了這種新輸入，因為第 1 階段就是在教它這件事。

### 參數的經濟性

LLaVA-1.5-7B 的拆解：
- CLIP ViT-L/14 @ 336：3.03 億（第 1 階段凍結，第 2 階段常解凍）。
- 投影器（兩層線性）：約 2200 萬可訓練參數。
- Llama-7B：70 億。
- 總計：73 億參數。第 2 階段可訓練的部分：完整的 70 億 + 2200 萬的投影器。

第 2 階段的訓練成本：8 張 A100 上約 20 小時。這就是那個關鍵數字 —— 一天、一個節點、可重現。這就是 LLaVA 之所以擴散開來的原因。

## 框架應用

`code/main.py` 實作了：

1. 用純 Python 寫的兩層 MLP 投影器（玩具規模是維度 16 → 32 → 32）。
2. 提示詞建構管線：系統提示詞 + 把 `<image>` 換成 N 個投影詞元 + 使用者輪次 + 助理生成的佔位符。
3. 一個視覺化工具，呈現那 576 個詞元的視覺區塊在 LLM 脈絡中長什麼樣（佔掉 2k／32k／128k 脈絡的百分比）。

## 產出交付

這一課產出 `outputs/skill-llava-vibes-eval.md`。給定一個 LLaVA 家族的檢查點，它會跑一套 10 題的手感評測（3 題字幕、3 題 VQA、2 題推理、2 題拒答），並回報一份人類讀得懂的計分卡。這不是基準測試；這是一次冒煙測試，用來確認投影器與 LLM 接得好不好。

## 練習

1. 算出 `1024 → 4096 → 4096` 這個兩層 MLP 投影器的可訓練參數量。含 GELU 與偏置，它佔 LLaVA-13B 的多少比例？

2. 為一個「拒答」情境建一段 LLaVA 提示詞 —— 影像中有一位私人個體。寫出預期的助理回應。LLaVA 為什麼應該零樣本就拒絕這件事？又需要什麼訓練資料來強化這種拒答？

3. 讀 LLaVA-NeXT 部落格文章中談 AnyRes 的段落。算出一張 1344x672 的影像在 AnyRes 之下的視覺詞元數。與 336x336 之下的基礎 576 個詞元做比較。

4. LLaVA 的第 1 階段投影器是用字幕上的 LM 損失訓練的。如果你跳過第 1 階段直接進第 2 階段（視覺指令微調）會怎樣？答案請引用 Prismatic VLMs 的消融研究（arXiv:2402.07865）。

5. LLaVA-Instruct-150k 用 GPT-4 搭配 COCO 字幕來生成指令。針對一個新領域（醫療 X 光片、衛星影像），描述生成領域指令的四步驟資料管線。每一步各可能出什麼錯？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|----------------|------------------------|
| 投影器 | 「MLP 橋」 | 帶 GELU 的兩層 MLP，把 ViT 維度映射到 LLM 維度 |
| 影像詞元 | 「<image> 佔位符」 | 提示詞中的標記，推論前會被換成 N 個投影後的視覺詞元 |
| 視覺指令微調 | 「LLaVA 第 2 階段」 | 在 GPT-4 生成的 (影像, 指令, 回應) 三元組上訓練 |
| 第 1 階段對齊 | 「投影器預訓練」 | 凍結 ViT 與 LLM，用字幕上的 LM 損失訓練投影器 |
| AnyRes | 「多裁切鋪排」 | 把高解析度影像切成一格一格的裁切網格，再把每格的視覺詞元串起來 |
| LLaVA-Instruct | 「GPT-4 生成的」 | 從 COCO 字幕 + GPT-4 合成出的 158k 組指令—回應配對 |
| 視覺編碼器凍結 | 「骨幹上鎖」 | CLIP 權重在第 1 階段不更新，有時第 2 階段也不更新 |
| ShareGPT4V | 「更好的字幕」 | 由 GPT-4V 生成的 100 萬則密集字幕，用來做更高品質的對齊 |
| VQA | 「視覺問答」 | 針對一張影像回答自由形式問題的任務 |
| Prismatic VLMs | 「設計空間論文」 | Karamcheti 2024 的消融研究，系統性地測試投影器與資料的各種選擇 |
