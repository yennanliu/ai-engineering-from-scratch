# Chameleon 與純詞元的早期融合多模態模型

> 目前為止我們看過的每個 VLM，都把影像與文字分開處理。視覺詞元來自視覺編碼器，流進投影器，然後才在 LLM 內部與文字相遇。視覺與文字的詞彙表從不重疊。Chameleon（Meta，2024 年 5 月）問了一句：如果它們重疊了呢？訓練一個 VQ-VAE，把影像變成一串取自共享詞彙表的離散詞元。於是每份多模態文件現在都是一條序列 —— 文字詞元與影像詞元交錯，共用單一個自迴歸損失。副作用是：模型能生成混合模態的輸出 —— 在單次推論呼叫中交替吐出文字與影像詞元。這一課會讀早期融合這套主張，並從頭到尾做一個玩具版。

**類型：** 實作
**程式語言：** Python (stdlib, VQ-VAE tokenizer + interleaved decoder)
**先修單元：** 階段 12 · 05、階段 8（生成式 AI）
**時間：** 約 180 分鐘

## 學習目標

- 說明共享詞彙表 + 單一損失，如何改變了模型做得到的事。
- 描述 VQ-VAE 如何把一張影像分詞成一條離散序列，好與 Transformer 的下一個詞元目標相容。
- 說出 Chameleon 的訓練穩定性技巧：QK-Norm、dropout 的擺放位置、LayerNorm 的順序。
- 把 Chameleon 與 BLIP-2 的 Q-Former 路線做比較，並描述各自在什麼時候是對的選擇。

## 問題所在

以 adapter 為基礎的 VLM（LLaVA、BLIP-2、Qwen-VL）把文字與影像當成兩種不同的東西。文字詞元走的是 `embed(text_token)`；影像走的是 `visual_encoder(image) → projector → ... pseudo_tokens`。模型有兩條輸入路徑，在中途才會合。

這帶來三個後果：

1. LLM 只能吃影像，不能吐影像。輸出只有文字。
2. 混合模態的文件（像文章那樣段落與影像交替）處理起來很彆扭 —— 你要嘛在模型之外解析多模態輸入，要嘛把多次生成串起來。
3. 分布不匹配。視覺詞元與文字詞元活在隱藏空間的不同區域，造成微妙的對齊問題。

Chameleon 否定了這個前提：影像不過就是一串取自共享詞彙表的離散詞元。在交錯的文件上訓練模型，一個損失、一個自迴歸解碼器，然後你就免費解鎖了混合模態生成。

## 核心概念

### 把 VQ-VAE 當影像分詞器

這個分詞器是一個向量量化的變分自編碼器。架構是：

- 編碼器：CNN + ViT，把影像映射成一張空間特徵圖，比方說 32x32 個維度 256 的特徵。
- 碼本：一份學習得來的 K 個向量的詞彙表（Chameleon 用 8192 個），維度同樣是 256。
- 量化：對每個空間特徵，用 L2 距離查出最近的碼本項目。把連續的特徵換成那個整數索引。
- 解碼器：一個 CNN，把量化後的特徵還原成像素。

訓練：VAE 重建損失 + commitment 損失 + 碼本損失。這些碼本索引，就構成了影像的一套離散字母表。

以 Chameleon 而言：一張影像變成 32*32 = 1024 個詞元，取自一個 8192 大小的詞彙表。再與文字詞元（來自 LLM 的 BPE 詞彙表，假設 32000）串起來。最終詞彙表：40192。Transformer 看到的是一條序列、一個損失。

### 共享詞彙表

Chameleon 的詞彙表結合了文字詞元、影像詞元與模態分隔符。每個詞元有唯一的 ID。輸入嵌入層把每個 ID 映射成一個 D 維的隱藏向量。輸出投影再把隱藏狀態映回詞彙表的 logits。softmax 挑出下一個詞元，不管它屬於哪個模態。

分隔符很重要：`<image>` 與 `</image>` 標籤把影像詞元序列夾在中間。生成時，如果模型吐出 `<image>`，下游軟體就知道接下來 1024 個詞元是要送去解碼器算出像素的 VQ 索引。

### 混合模態生成

推論就是在共享詞彙表上做下一個詞元預測。範例提示詞：「畫一隻貓並描述牠。」Chameleon 吐出：

```
<image> 4821 1029 2891 ... (1024 image tokens) </image>
The cat is orange, sitting on a windowsill...
```

順序由模型自主決定 —— 它可能先圖後文、先文後圖，或交錯進行。同一個解碼器、同一個損失。

相較之下，adapter 式 VLM 的生成只有文字。Chameleon 把「模型的輸出模態」這個問題重新打開了。

### 訓練穩定性 —— QK-Norm、dropout、LayerNorm 順序

早期融合的訓練在大規模下並不穩定。Chameleon 的論文記錄了三個技巧：

- QK-Norm。在注意力內部，於點積之前對 query 與 key 的投影套用 LayerNorm。這能防止深層處 logit 量級爆炸。2024 年之後有多個大模型都在用。
- dropout 的擺放位置。在每一次殘差相加之後都做 dropout，而不只是在注意力與 MLP 之後。當來自影像詞元的梯度可能主導全局時，就需要更多正則化。
- LayerNorm 的順序。殘差分支上用 Pre-LN（標準做法），再於最後一個區塊的跳接上多加一層 LN。這能穩定最終層的梯度流。

少了這些技巧，340 億參數的 Chameleon 訓練在多個檢查點上都發散了。有了它們，才收斂。這份訓練配方，與架構本身同樣是這篇論文的貢獻。

### 分詞器的重建天花板

VQ-VAE 是有損的。在 8192 個碼本項目、每張 512x512 影像 1024 個詞元之下，重建的 PSNR 大約卡在 26 到 28 dB。這足以做出認得出來的影像生成，但明顯比連續空間的擴散模型差（Stable Diffusion 3 能達到 32 dB 以上）。

分詞器就是那個瓶頸。更好的分詞器（MAGVIT-v2、IBQ、SBER-MoVQGAN）能把天花板往上抬。Emu3（見單元 12.12）光靠一個更好的分詞器，就達到了 SDXL 等級的生成品質。

### Chameleon 對上 BLIP-2／LLaVA

Chameleon（早期融合、共享詞彙表）：
- 一個損失、一個解碼器。
- 能生成混合模態輸出。
- 分詞器就是品質天花板。
- 昂貴：推論路徑上，每生成一張影像就要跑一次 VQ-VAE 解碼器。

BLIP-2／LLaVA（後期融合、分離的雙塔）：
- 只能吃視覺、吐文字。
- 重用預訓練好的 LLM。
- 在理解任務上沒有分詞器瓶頸。
- 便宜：單次前向傳播。

依任務來挑。如果你需要影像生成，選 Chameleon 家族。如果你只需要理解，adapter 式 VLM 更簡單，也重用了更多預訓練計算。

### Fuyu 與 AnyGPT

Fuyu（Adept，2023）是一種相關的路線：徹底跳過獨立的視覺編碼器，把原始影像 patch 當成詞元，直接餵進 LLM 的輸入投影，不用分詞器。比 Chameleon 更簡單，但失去了共享詞彙表帶來的輸出生成能力。

AnyGPT（Zhan 等人，2024）把 Chameleon 擴展到四種模態：文字、影像、語音、音樂。每一種都用同樣的 VQ-VAE 把戲，共享同一個 Transformer。做到任意對任意的生成。單元 12.16 會談得更多。

## 框架應用

`code/main.py` 做了一個玩具版的端到端早期融合模型：

- 一個迷你的 VQ-VAE 風格量化器，把 8x8 的 patch 映射成碼本索引（K=16）。
- 一份共享詞彙表：(文字 id 0..31) + (影像 id 32..47) + (分隔符 48, 49)。
- 一個玩具版的自迴歸解碼器（bigram 表），在合成字幕 + 影像詞元序列上訓練。
- 一個取樣迴圈，給定提示詞就交替吐出文字與影像詞元。

程式碼刻意把 Transformer 做得極小（bigram），好讓你能從頭到尾追蹤訊號的流向。

## 產出交付

這一課產出 `outputs/skill-tokenizer-vs-adapter-picker.md`。給定一份產品規格（只要理解，還是理解 + 生成；所需的影像品質；成本預算），它會在 Chameleon 家族（早期融合）與 LLaVA 家族（後期融合）之間做出選擇，並用量化的經驗法則為之辯護。

## 練習

1. Chameleon 用 K=8192 個碼本項目，每張 512x512 影像 1024 個詞元。估算它相對於一張 24 位元 RGB 影像的壓縮比。這有損嗎？損多少？

2. 一張 4K 影像（3840x2160）在同樣的 VQ-VAE 密度下會產生多少影像詞元？一個 Chameleon 風格的模型能在單次推論呼叫中生成一張 4K 影像嗎？先崩掉的會是什麼 —— 脈絡、分詞器品質，還是 KV 快取？

3. 用純 Python 實作 QK-Norm。給定一個 64 維的 query 與 key，列出 LayerNorm 前後的點積。為什麼在深層處控制量級很重要？

4. 讀 Chameleon 第 2.3 節關於訓練穩定性的部分。描述論文在 34B、未使用 QK-Norm 時觀察到的確切失敗模式。那個「範數爆炸」的特徵長什麼樣？

5. 擴充那個玩具解碼器，讓它在純文字提示詞下吐出混合模態回應。在訓練資料分布為 60% 先文字／40% 先影像的條件下，量測模型選擇先出影像與先出文字的頻率。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| 早期融合 | 「統一詞元」 | 影像從第一步起就被轉換成離散詞元，與 Transformer 共享同一份詞彙表 |
| VQ-VAE | 「影像分詞器」 | CNN + ViT + 碼本，把影像映射成 Transformer 預測得了的整數索引 |
| 共享詞彙表 | 「一本字典」 | 單一個詞元 ID 空間，涵蓋文字 + 影像 + 模態分隔符 |
| QK-Norm | 「注意力穩定器」 | 在 query 與 key 做點積之前對它們套用 LayerNorm，防止範數暴增 |
| 混合模態生成 | 「文字 + 影像輸出」 | 單次推論就自主產出交錯的文字與影像詞元 |
| 碼本大小 | 「K 個項目」 | VQ-VAE 可量化到的離散向量數量；在壓縮率與保真度之間權衡 |
| 分詞器天花板 | 「重建上限」 | 解碼 VQ 詞元所能達到的最佳 PSNR；它框住了模型的影像品質 |
