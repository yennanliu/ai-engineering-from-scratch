# 從 CLIP 到 BLIP-2 —— 把 Q-Former 當成模態橋樑

> CLIP 能對齊影像與文字，卻沒辦法生成字幕、回答問題，或撐起一段對話。BLIP-2（Salesforce，2023）用一座小小的可訓練橋樑解決了這件事：32 個可學習的 query 向量，透過交叉注意力去關注一個凍結 ViT 的特徵，然後直接插進一個凍結 LLM 的輸入串流。1.88 億參數的橋樑，把一個 11B 的 LLM 接到了 ViT-g/14 上。一路到 2026 年，每一個以 adapter 為基礎的 VLM —— MiniGPT-4、InstructBLIP、LLaVA 的表親們 —— 都是它的後裔。這一課會讀 Q-Former 的架構、解釋它的兩階段訓練，並做一個玩具版，把視覺詞元餵進一個凍結的文字解碼器。

**類型：** 實作
**程式語言：** Python (stdlib, cross-attention + learnable-query demo)
**先修單元：** 階段 12 · 02（CLIP）、階段 7（Transformers）
**時間：** 約 180 分鐘

## 學習目標

- 說明為什麼在凍結的視覺編碼器與凍結的 LLM 之間放一個可訓練的瓶頸，在成本與穩定性上都勝過端到端微調。
- 實作一個交叉注意力區塊，讓一組固定的可學習 query 去關注外部的影像特徵。
- 走一遍 BLIP-2 的兩階段預訓練：先做表徵（ITC + ITM + ITG），再做生成（在凍結解碼器上的 LM 損失）。
- 把 Q-Former 與 LLaVA 使用的那個更簡單的 MLP 投影器做比較，並論證各自在什麼時候勝出。

## 問題所在

你有一個凍結的 ViT，每張影像產出 256 個維度 1408 的 patch 詞元。你有一個凍結的 7B LLM，它期待的是維度 4096 的詞元嵌入。最直白的橋樑 —— 一層從 1408 到 4096 的線性層 —— 能動，但把全部 256 個 patch 詞元餵進 LLM 的脈絡，等於每張影像多花 256 個詞元。一批 32 張影像下來，光是視覺模態就吃掉 8192 個詞元。

BLIP-2 的問題是：你能不能把 256 個詞元的影像表徵壓縮成少得多的詞元（比方說 32 個），同時保留足夠的資訊，讓 LLM 還能寫字幕、回答問題、對影像進行推理？以及，你能不能在完全不動凍結骨幹的前提下訓練這座橋，讓訓練成本就只有橋樑本身的參數？

答案是：一個 Q-Former。32 個可學習的「query」向量，去交叉關注 ViT 的 patch 詞元，產出一份 32 個詞元的視覺摘要供 LLM 取用。總共 1.88 億參數。在碰到 LLM 之前，先用對比、匹配與生成三種目標訓練過。

## 核心概念

### 可學習的 query

Q-Former 的核心把戲：與其讓 LLM 的文字詞元去關注影像 patch，不如引入一組 32 個全新的可學習 query 向量 `Q`，讓*它們*去關注影像 patch。這些 query 是模型的參數 —— 它們在訓練中被學出來，而且每張影像用的都是同樣那 32 個 query。

交叉注意力之後，每個 query 都握著一份影像的壓縮摘要 —— 「描述主要物件」、「描述背景」、「數一數物件」等等。這些 query 並不是真的照語意標籤各司其職；它們學到的是任何能讓下游損失下降的編碼方式。

### 架構

Q-Former 是一個小型 Transformer（12 層、約 1 億參數），有兩條路徑：

1. query 路徑：32 個 query 向量先流過自注意力（彼此之間），再對凍結 ViT 的 patch 詞元做交叉注意力，然後過 FFN。
2. 文字路徑：一個類 BERT 的文字編碼器，與 query 路徑共享自注意力與 FFN 權重。文字路徑上的交叉注意力是關閉的。

訓練時兩條路徑都跑。query 與文字透過共享的自注意力互動，這表示在需要的任務上（ITM、ITG），query 可以以文字為條件。推論時要交棒給 VLM，就只讓 query 流過，得到 32 個視覺詞元。

### 兩階段訓練

BLIP-2 分兩階段預訓練：

第 1 階段：表徵學習（沒有 LLM）。三個損失：
- ITC（影像—文字對比）：在池化後的 query 詞元與文字 CLS 詞元之間，做 CLIP 式的對比學習。
- ITM（影像—文字匹配）：二元分類器 —— 這組影像—文字配對是一組嗎？搭配難負例挖掘。
- ITG（影像接地的文字生成）：以 query 為條件，在文字上接一個因果 LM head。逼著 query 去編碼那些能被文字生成出來的內容。

只有 Q-Former 在訓練。ViT 是凍結的。完全不涉及 LLM。

第 2 階段：生成式學習。接上一個凍結的 LLM（OPT-2.7B 或 Flan-T5-XL 等）。用一層小小的線性層，把 32 個 query 輸出投影到 LLM 的嵌入維度。把它們接在文字提示詞前面。在「提示詞 + 影像 + 字幕」串接起來的序列上，用 LM 損失只訓練那個線性投影與 Q-Former。

第 2 階段結束後，Q-Former + 投影就構成完整的視覺 adapter。推論時：影像 → ViT → Q-Former → 線性投影 → 接在文字前面 → 凍結的 LLM 吐出輸出。

### 參數的經濟學

BLIP-2 用 ViT-g/14（11 億，凍結）+ OPT-6.7B（67 億，凍結）+ Q-Former（1.88 億，訓練）= 總共 80 億參數，其中 1.88 億有在訓練。光看 Q-Former，大約只佔整套堆疊參數的 2.4%。訓練成本也如實反映了這點：幾張 A100 跑幾天，相對於端到端要跑幾週。

品質方面：BLIP-2 在零樣本 VQA 上追平甚至勝過 Flamingo-80B，體積卻小了 50 倍。這座橋是有效的。

### InstructBLIP 與能感知指令的 Q-Former

InstructBLIP（2023）替 Q-Former 多加了一個輸入：指令文字本身。到了交叉注意力時，query 現在同時能取用影像 patch 與指令。query 因此可以依指令各自特化（「數一數車子」、「描述氛圍」），而不是只學一份固定的摘要。在留出任務上有基準分數的提升。

### MiniGPT-4 與只訓練投影器的做法

MiniGPT-4 保留了 Q-Former，但只訓練輸出端的線性投影，其他全部凍結。便宜，但代價是品質 —— 那些 query 是 BLIP-2 的，不是你的。適合快速迭代，不是最好的架構。

### LLaVA 為什麼走了更簡單的路

LLaVA（2023，見單元 12.05）把 Q-Former 換成一個樸素的兩層 MLP，把每一個 ViT patch 詞元都投影進 LLM 空間 —— 以 24x24 的網格來說是每張影像 576 個詞元，全部餵給 LLM。壓縮效果更差，但讓 LLM 能直接關注原始 patch。這在當時是有爭議的；到了 2023 年底它成了主流，因為視覺指令資料（LLaVA-Instruct-150k）證明了 MLP 可以被訓練到保留足夠的訊號。取捨在於：LLaVA 的脈絡填得更快，但它能自然地擴展到多影像與影片。

到了 2026 年，這個領域分成兩派：詞元預算要緊的地方（長影片、多影像）Q-Former 存活下來；把每個詞元的原始品質擺第一的地方，則由 MLP 投影器主導。

### 帶閘門的交叉注意力：祖先 Flamingo

Flamingo（見單元 12.04）出現在 BLIP-2 之前，用的是同樣的交叉注意力想法，但放在每一層凍結的 LLM 上，而不是作為單一的一座橋。BLIP-2 證明了你只壓縮到輸入層一樣行得通。Gemini 與 Idefics 則兩者兼採：交錯的輸入詞元，再加上選配的帶閘門交叉注意力，以支援脈絡內的少樣本學習。

### 2026 年的後裔們

- Q-Former：BLIP-2、InstructBLIP、MiniGPT-4，以及多數基於詞元預算考量的影片—語言模型。
- Perceiver resampler：Flamingo 的變體（見單元 12.04）；Idefics 家族、Eagle、OmniMAE。
- MLP 投影器：LLaVA、LLaVA-NeXT、LLaVA-OneVision、Cambrian-1。
- 注意力池化：VILA、PaliGemma。

四者都是有效的。決定性的問題是：你受限的是詞元預算，還是每個詞元的品質。

## 框架應用

`code/main.py` 用 stdlib 做出一個 Q-Former 風格的交叉注意力：

1. 模擬 256 個影像 patch 詞元（維度 128）。
2. 建立 32 個可學習的 query（維度 128）。
3. 跑縮放點積的交叉注意力（Q 來自 query，K/V 來自 patch）。
4. 用一層線性層投影到 LLM 維度（512）。
5. 輸出那 32 個可供 LLM 使用的視覺詞元。

所有數學都是純 Python（在向量上跑巢狀迴圈）。是玩具，但形狀正確。程式會把注意力權重矩陣印出來，讓你看見每個 query 各自從哪些 patch 取材。

## 產出交付

這一課產出 `outputs/skill-modality-bridge-picker.md`。給定一份目標 VLM 設定（視覺編碼器的詞元數、LLM 的脈絡預算、部署限制、品質目標），它會在 Q-Former、MLP 與 Perceiver resampler 之間給出建議，附上簡短理由與每種橋樑的參數量估算。

## 練習

1. 用 PyTorch 實作那個交叉注意力區塊。驗證在 32 個 query 與 256 個 key/value 之下，注意力權重矩陣是 32 x 256，且經過 softmax 後每一列加總為 1。

2. 在 BLIP-2 第 1 階段，Q-Former 同時跑三個損失：ITC、ITM、ITG。用虛擬碼寫出各自的前向簽章。哪一個需要文字編碼器路徑是啟用的？

3. 比較參數量：Q-Former（12 層、隱藏維度 768）對上一個兩層的 MLP 投影器（1408 → 4096，兩層）。在多大的 LLM 規模下，1.88 億參數的 Q-Former 成本能在訓練效率上回本？

4. 讀 BLIP-2 論文（arXiv:2301.12597）第 3.2 節關於 Q-Former 如何初始化的部分。說明為什麼從 BERT-base 初始化（而不是隨機）能加速收斂。

5. 對一段 10 分鐘、以 1 FPS 取樣成 60 個畫格的影片，算出（Q-Former → 每畫格 32 詞元）與（MLP 投影器 → 每畫格 576 詞元）之下每畫格的詞元成本。哪一個塞得進 128k 詞元的 LLM 脈絡視窗？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|----------------|------------------------|
| Q-Former | 「查詢式 Transformer」 | 一個帶 32 個可學習 query 向量的小型 Transformer，用交叉注意力去關注凍結的 ViT 特徵 |
| 可學習 query | 「視覺版的軟提示詞」 | 一組固定的參數，充當交叉注意力的 query 那一側；每個模型各自學一份，所有輸入共用 |
| 交叉注意力 | 「Q 從這邊來，K/V 從那邊來」 | query、key、value 來自不同來源的注意力；query 就是這樣從 ViT patch 取材的 |
| ITC | 「影像—文字對比」 | 套用在 Q-Former 池化 query 與文字 CLS 之間的 CLIP 式損失 |
| ITM | 「影像—文字匹配」 | 在難負例挖掘出的配對上做二元分類；逼著 query 去分辨細粒度的不匹配 |
| ITG | 「影像接地的文字生成」 | 以 query 為條件生成文字的因果 LM 損失；逼著 query 去編碼可被文字解碼出來的內容 |
| 兩階段預訓練 | 「先表徵、後生成」 | 第 1 階段單獨訓練 Q-Former（ITC／ITM／ITG）；第 2 階段接上凍結的 LLM，只訓練投影 + Q-Former |
| 凍結骨幹 | 「不要微調」 | 視覺編碼器與 LLM 的權重固定不動；只有橋樑在訓練 |
| 投影 head | 「線性映到 LLM 維度」 | 最後那層線性層，把 Q-Former 的輸出映射到 LLM 的嵌入維度 |
| Perceiver resampler | 「Flamingo 的版本」 | 類似的可學習 query 交叉注意力，Flamingo 把它放在每一層而非當成單一的一座橋 |
