# InternVL3：原生多模態預訓練

> InternVL3 之前的每一個開放 VLM，走的都是同一套三步驟配方：拿一個在數兆文字詞元上訓練好的文字 LLM，硬接上一個視覺編碼器，再把接縫微調一下。這行得通，但欠下了對齊債 —— 那個文字 LLM 把整份預訓練預算都花在純文字上，本來就不懂視覺詞元。當你事後才加上視覺，LLM 就得在不遺忘文字的前提下，重新學會如何把視覺輸入關聯到它的文字推理。InternVL3（Zhu 等人，2025 年 4 月）否定了這種事後補救的路線：一次預訓練，文字與多模態從第一步起就交錯在一起。結果是，在 780 億參數的開放模型上，於 MMMU-Pro 追平 Gemini 2.5 Pro。這一課會讀原生預訓練的論據，以及一旦這麼做會有什麼改變。

**類型：** 學習
**程式語言：** Python (stdlib, training-corpus mixer)
**先修單元：** 階段 12 · 05、階段 12 · 07（配方）
**時間：** 約 120 分鐘

## 學習目標

- 說明事後補救式的 VLM 訓練為何會累積對齊債，並舉出三項可量測的症狀（災難性遺忘、答案漂移、圖文不一致）。
- 描述 InternVL3 的原生預訓練語料配方，以及「文字：交錯：字幕」這個比例為什麼要緊。
- 把 V2PE（可變視覺位置編碼）與 Qwen2-VL 的 M-RoPE 做比較。
- 說出視覺解析度路由器（ViR）與視覺—語言解耦（DvD）這兩項部署最佳化。

## 問題所在

事後補救式的 VLM 訓練是預設做法。LLaVA、BLIP-2、Qwen-VL、Idefics —— 全都是拿一個已經預訓練好的 LLM（Llama、Vicuna、Qwen、Mistral）再加上視覺。訓練階段通常長這樣：

1. 凍結的 LLM + 凍結的視覺編碼器 + 可訓練的投影器，在字幕配對上訓練以對齊嵌入。
2. 解凍 LLM，在指令資料上訓練（LLaVA-Instruct、ShareGPT4V）。
3. 選配的任務專屬微調。

對齊債會冒出三種症狀：

- 災難性遺忘。事後補救的 VLM 會忘掉純文字技能。GSM8K 分數掉 5 到 10 分。Hellaswag 分數也掉。純文字的代理程式表現退步。
- 答案漂移。同一個視覺問題換個說法，就得到不同答案。視覺編碼器與 LLM 的連結，比 LLM 自家詞元之間的連結來得弱。
- 圖文不一致。VLM 可以先正確描述一張影像，接著回答一個與它自己描述相矛盾的問題。視覺詞元參與 LLM 內部一致性檢查的方式，與文字不一樣。

這些症狀都有充分的文獻記載。MM1.5 第 4 節把它們量化了。LLaVA-OneVision 的消融實驗也暗示了這些現象。原生預訓練就是答案。

## 核心概念

### 原生多模態預訓練

InternVL3 是在一份從第一步起就原生多模態的語料上從零訓練。配方是：

- 40% 純文字資料（FineWeb、Proof-Pile-2 等）
- 35% 交錯的影像—文字資料（OBELICS、MMC4 風格）
- 20% 成對的影像—字幕資料
- 5% 影片—文字資料

從第一次梯度更新起，視覺詞元、文字詞元與跨模態互動就全部參與同一個損失。沒有對齊預訓練，沒有投影器凍結階段，也沒有需要事後補救的災難性遺忘。

基礎模型的訓練是單一階段。之後才做指令微調，但基礎模型早已把視覺詞元當成一等公民來理解。

### V2PE（可變視覺位置編碼）

Qwen2-VL 用的是固定軸配置的 M-RoPE。InternVL3 引入了 V2PE：位置編碼依模態型別（文字、影像、影片）而異，並帶可學習的縮放。實務上：

- 文字詞元拿一維位置（文字索引）。
- 影像 patch 拿二維位置（列、行）。
- 影片畫格拿三維位置（時間、列、行）。

三者共用同一個 RoPE 頻率基數，但每個頻帶分到多少隱藏維度，是一個學習得來的參數，而非固定的切分。這給了預訓練期間在時間與空間頻率解析度之間權衡的自由。

V2PE 的消融主張是：在相同計算量下，影片基準比 M-RoPE 高 1 到 2 分。稱不上革命，但更乾淨。

### 視覺解析度路由器（ViR）

這是部署最佳化。不是所有影像都需要全解析度編碼。一張只有一個低細節物件的照片，用 1280px 原生解析度編碼就是在浪費詞元。ViR 是一個小型分類器，在編碼之前先預測回答該問題所需的最低解析度。

路由分三層：低解析度（256 詞元）、中（576）、高（2048 以上）。在生產流量中，有 60% 的查詢用低或中就夠了。淨效果：在同等品質下吞吐量提升 2 到 3 倍。

### 視覺—語言解耦部署（DvD）

當你在服務一個大型 VLM 時，視覺編碼器每張影像只跑一次，但 LLM 得為每個輸出詞元自迴歸地跑一遍。這兩個元件的瓶頸不同（視覺 = 卷積與注意力所需的 GPU 記憶體頻寬；LLM = KV 快取）。DvD 把它們拆到不同的 GPU 上，中間以串流銜接。

以一個 8B 加 4 億參數編碼器的模型而言，DvD 讓每個節點的吞吐量比同機部署大約翻倍。

### 單階段對多階段的品質

InternVL3 的主要基準主張是：在 780 億參數下，於 MMMU-Pro 追平 Gemini 2.5 Pro。在 380 億參數下，追平 GPT-4o。在 80 億參數下，領先開放 8B 排行榜。全都是靠「單階段預訓練 + 指令微調」這份配方。

對齊債這個假說是可量測的：每換取一單位的視覺基準提升，InternVL3-8B 損失的文字基準分數（MMLU、GSM8K）比 Qwen2.5-VL-7B 少。這個模型更像個通才，因為訓練是一整塊，不是兩塊。

### InternVL3.5 與 InternVL-U

InternVL3.5（2025 年 8 月）把這份配方擴大規模。同樣的原生預訓練路線，更多資料，更多參數。MMMU 的進步是漸進式的。

InternVL-U（2026）加上了統一生成 —— 在同一個骨幹上疊 MMDiT head 來輸出影像。這個「U」代表「Understanding + generation（理解 + 生成）」，追的是 Transfusion 式的統一模型（見單元 12.13）。同一個原生預訓練骨幹，同時撐起理解與生成兩種 head。

### 原生預訓練的取捨

原生預訓練不是免費的：

- 計算。從零訓練一個新的 VLM，成本和訓練一個文字 LLM 一樣 —— 數百萬 GPU 小時。事後補救式的適配則重用既有的 LLM 權重，省下大部分成本。
- 資料。規模夠大的交錯影像—文字語料很稀有。OBELICS 有 1.41 億份文件；MMC4 有 5.71 億份。而純文字動輒 15 兆詞元。多模態預訓練資料的稀缺是一道硬限制。
- 基礎 LLM 的重用。原生預訓練放棄了日後直接換上新 LLM 的選項。事後補救則讓你只要重訓 adapter，就能把 Llama-3.1 換成 Llama-4。

InternVL3 押的注是：對齊債比失去重用性更糟。基準數據支持這個主張。而其生產成本，也擋住了後續實驗室廉價複製的可能。事後補救式的 VLM 仍會繼續存在，因為對多數專案來說它還是比較便宜。

## 框架應用

`code/main.py` 是一個訓練語料混合器兼 ViR 路由器模擬器。它會：

- 接收一份目標語料配方（%文字、%交錯、%字幕、%影片），並算出各模態的預期步數。
- 在一批查詢上模擬 ViR 路由（分布：50% 低細節、30% 中、20% 高細節），並回報平均詞元數。
- 依編碼器與 LLM 的 FLOPs，回報 DvD 的吞吐量估算。
- 印出一份事後補救對原生預訓練的並列比較，涵蓋參數、計算、資料與預期的對齊債症狀。

## 產出交付

這一課產出 `outputs/skill-native-vs-posthoc-auditor.md`。給定一份提案中的 VLM 訓練計畫，它會稽核該走原生還是事後補救、標記對齊債的風險，並建議一份語料配方。當你在為一個新的開放 VLM 專案估算規模、需要挑訓練策略時就用它。

## 練習

1. 估算 InternVL3-8B（原生預訓練）與 LLaVA-OneVision-7B（事後補救）之間的計算量差距。GPU 小時的比例大約是多少？這道落差要怎麼解釋？

2. InternVL3 回報的是 40% 文字／35% 交錯／20% 字幕／5% 影片。如果你的目標任務以影片為主，提出一份新的比例，並論證為什麼基礎模型仍然需要可觀的文字與字幕資料。

3. 讀 MM1.5 第 4 節關於遺忘的部分。指出事後補救式訓練退步最嚴重的到底是哪一項基準。那次退步的代價有多大？

4. ViR 把 60% 的流量導向低解析度編碼。它會把哪些查詢導錯（該用高解析度卻送去低解析度）？提出三種路由器的失敗模式。

5. DvD 把視覺與 LLM 拆到不同的 GPU 上。在什麼樣的流量型態下，DvD 反而會傷害吞吐量而非幫上忙？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| 原生多模態預訓練 | 「從零一起練」 | 文字 + 影像 + 影片詞元從第 1 步起就參與損失，而不是後來才硬接上去 |
| 對齊債 | 「事後補救的罰則」 | 把視覺硬接到一個凍結 LLM 上所造成、可量測的文字技能與答案一致性退步 |
| V2PE | 「可變視覺位置編碼」 | 依模態各自可學習的位置編碼配置；InternVL3 的 M-RoPE 後繼者 |
| ViR | 「解析度路由器」 | 在編碼之前，為每個查詢挑出所需最低解析度的小型分類器，藉此省下推論詞元 |
| DvD | 「解耦部署」 | 視覺編碼器放一張 GPU、LLM 放另一張，中間以串流交棒；讓大型 VLM 的吞吐量翻倍 |
| InternVL-U | 「統一理解 + 生成」 | 2026 年的後續版本，在原生預訓練骨幹上加了影像生成 head |
| 交錯語料 | 「OBELICS／MMC4」 | 文字與影像依自然閱讀順序排列的文件；原生預訓練的原料 |
