# ColPali 與視覺原生的文件 RAG

> 傳統 RAG 把 PDF 解析成文字、切成區塊、把區塊嵌入、存成向量。每一步都在流失訊號：OCR 丟掉圖表資料，切塊打斷表格列，文字嵌入無視圖片。ColPali（Faysse 等人，2024 年 7 月）問了一個更簡單的問題：為什麼要抽取文字？直接用 PaliGemma 把頁面影像嵌入，用 ColBERT 式的後期互動做檢索，把文件所承載的版面、圖片、字型與格式訊號通通留下來。公開的基準數據：在視覺豐富的文件上，端到端準確率比文字 RAG 高 20% 到 40%。ColQwen2、ColSmol 與 VisRAG 延伸了這套模式。這一課會讀視覺原生 RAG 的主張，並做一個迷你的類 ColPali 索引器。

**類型：** 實作
**程式語言：** Python (stdlib, multi-vector indexer + MaxSim scorer)
**先修單元：** 階段 11（LLM 工程 —— RAG 基礎）、階段 12 · 05（LLaVA）
**時間：** 約 180 分鐘

## 學習目標

- 說明雙編碼器檢索（每份文件一個向量）與後期互動檢索（每份文件多個向量）之間的差異。
- 描述 ColBERT 的 MaxSim 運算，以及 ColPali 如何把它從文字詞元類推到影像 patch。
- 做一個迷你的類 ColPali 索引器：頁面 → patch 嵌入 → 對查詢詞嵌入做 MaxSim → top-k 頁面。
- 在發票／財務報告的使用情境上，比較「ColPali + Qwen2.5-VL 生成器」與「文字 RAG + GPT-4」。

## 問題所在

在 PDF 上做文字 RAG，會丟掉文件的大部分內容。一份財報的第三季營收成長通常在圖表裡；一份醫療報告的發現在標註過的影像裡；一份法律合約的簽名欄是版面事實，不是文字事實。

文字 RAG 的管線：

1. PDF → 透過 OCR／pdftotext 轉成文字。
2. 文字 → 300 到 500 個詞元的區塊。
3. 區塊 → 雙編碼器嵌入（一個向量）。
4. 使用者查詢 → 嵌入 → 餘弦相似度 → top-k 區塊。
5. 區塊 + 查詢 → LLM。

五個有損的步驟。圖表沒被捕捉到。表格被切塊拆散。多欄版面被壓平。圖片註記消失。

ColPali 的修正是：跳過 OCR，直接把頁面影像嵌入。用 ColBERT 式的後期互動做檢索，好讓模型能在查詢時關注細粒度的 patch。

## 核心概念

### ColBERT（2020）

ColBERT（Khattab 與 Zaharia，arXiv:2004.12832）是一種文字檢索方法。它不是每份文件一個向量，而是每個詞元一個向量。查詢時：

- 查詢詞元有自己的嵌入（N_q 個向量）。
- 文件詞元有嵌入（N_d 個向量，通常已快取）。
- 分數 = 對每個查詢詞元，取它與所有文件詞元餘弦相似度的最大值，再加總：Σ_i max_j cos(q_i, d_j)。

這就是 MaxSim 運算。每個查詢詞元「挑」出它最匹配的那個文件詞元。最終分數是這些值的總和。

優點：召回率強，能處理詞級語意。缺點：每份文件 N_d 個向量，儲存很貴。

### ColPali

ColPali（Faysse 等人，arXiv:2407.01449）把 ColBERT 這套模式套用到影像上。

- 每一頁由 PaliGemma（ViT + 語言）編碼成 patch 嵌入：每頁 N_p 個向量。
- 每段使用者查詢（文字）被編碼成查詢詞元嵌入：N_q 個向量。
- 分數 = Σ_i max_j cos(q_i, p_j)，也就是在查詢文字詞元與頁面影像 patch 之間做 MaxSim。
- 依總分取回 top-k 頁面。

在文件匯入時：用 PaliGemma 把每一頁嵌入，把全部 patch 嵌入存起來。查詢時：把查詢詞元嵌入，對所有已存的頁面嵌入計算 MaxSim，回傳 top-k 頁面。

優點：在視覺豐富的文件上，端到端勝過文字 RAG 20% 到 40%。每個 patch 向量都捕捉了局部的版面與內容。

缺點：每頁 N_p 個 patch × 4 位元組浮點數 × D 維向量 = 儲存量成長很快。可用 PQ／OPQ 量化緩解。

### ColQwen2 與 ColSmol

ColQwen2（illuin-tech，2024 到 2025）把 PaliGemma 換成 Qwen2-VL。基礎編碼器更好，檢索也更好。

ColSmol 是給本機／邊緣使用的小規模變體。一個約 10 億參數的 ColSmol 檢索器，在消費級 GPU 上就跑得動。

### VisRAG

VisRAG（Yu 等人，arXiv:2410.10594）是另一種變體：它不在 patch 上做 MaxSim，而是先用 VLM 把每一頁池化成單一向量，再用雙編碼器檢索。索引更快、儲存更小，但召回率較弱。

品質對成本的取捨：要品質選 ColPali，要規模選 VisRAG。

### M3DocRAG

M3DocRAG（Cho 等人，arXiv:2411.04952）把多模態檢索延伸到跨多頁、多文件的推理。它跨文件取回頁面，為 VLM 組出一份多頁的脈絡。

### ViDoRe —— 那個基準

ColPali 的配套基準。視覺文件檢索評測。任務涵蓋財務報告、科學論文、行政文件、病歷、手冊。指標：nDCG@5。

ColPali-v1 在 ViDoRe 上約 80% 的 nDCG@5；同一批文件上的文字 RAG 只有約 50% 到 60%。

### 端到端的 RAG 管線

要做一套視覺原生 RAG：

1. 匯入：PDF → 頁面影像 → PaliGemma 編碼 → 儲存全部 patch 嵌入。
2. 查詢：使用者文字 → 查詢詞元嵌入 → 對所有已索引頁面做 MaxSim → top-k 頁面。
3. 生成：top-k 頁面影像 + 查詢 → VLM（Qwen2.5-VL 或 Claude）→ 答案。

全程沒有 OCR。圖片、圖表、字型、版面全都流進了答案裡。

### 儲存量的數學

一份 50 頁的財務報告，每頁 729 個 patch、128 維嵌入：

- ColPali：50 * 729 * 128 * 4 位元組 = 約 18 MB 原始量，經 PQ 後約 4 MB。
- 文字 RAG：50 個區塊 * 768 維 * 4 位元組 = 約 150 kB。

ColPali 每份文件的儲存量大約是 30 倍。在規模化時，OPQ／PQ 能把它壓到約 5 到 10 倍，通常還可以接受。

### 文字 RAG 仍然勝出的場合

- 沒有版面訊號的純文字文件（維基文章、聊天記錄）。文字 RAG 更簡單，儲存也更便宜。
- 儲存成本主導一切的數百萬頁級檔案庫。
- 嚴格的法規要求，必須在檢索之外同時提供可抽取的 OCR 文字。

2026 年的其他一切 —— 財務報告、科學論文、法律合約、病歷、UX 文件 —— 都是視覺原生 RAG 勝出。

## 框架應用

`code/main.py`：

- 玩具版 patch 編碼器：把一個「頁面」（一小格特徵向量網格）映射成一組 patch 嵌入。
- MaxSim 計分器：在一組查詢詞元嵌入與一組頁面 patch 之間，算出 ColBERT 式的分數。
- 索引 5 個玩具頁面，跑 3 段查詢，回傳帶分數的 top-k。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| 後期互動 | 「ColBERT 式」 | 用逐詞元或逐 patch 的嵌入 + MaxSim 做檢索，而不是單一份文件向量 |
| MaxSim | 「在 patch 上取最大」 | 對每個查詢詞元，挑出相似度最高的那個文件詞元；再跨查詢加總 |
| 雙編碼器 | 「單向量」 | 每份文件一個向量；較快但失去細粒度 |
| 多向量 | 「每份文件多個向量」 | 每份文件／頁面存 N_p 個向量；儲存成本上升但召回率改善 |
| Patch 嵌入 | 「頁面特徵」 | 由 VLM 編碼器產出、每個影像 patch 一個向量，並逐頁快取 |
| ViDoRe | 「視覺文件基準」 | ColPali 為視覺文件檢索所推出的基準套組 |
| PQ 量化 | 「乘積量化」 | 在維持向量相似度的同時，把儲存量縮小約 8 倍的壓縮法 |
