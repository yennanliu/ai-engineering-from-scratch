# 多模態代理程式與電腦操作（總結專案）

> 2026 年的前沿產品，是一個能讀截圖、點按鈕、在網頁 UI 中導覽、填表單，並端到端完成整套工作流程的多模態代理程式。SeeClick 與 CogAgent（2024）證明了 GUI 接地這個基本單位。Ferret-UI 補上了行動裝置。ChartAgent 為圖表引入了視覺工具使用。VisualWebArena 與 AgentVista（2026）則是前沿正在追逐的基準 —— 即便是 Gemini 3 Pro 與 Claude Opus 4.7，在 AgentVista 的困難任務上也只拿到約 30%。這個總結專案會把階段 12 的每一條線都收攏起來：感知（高解析度 VLM）、推理（會用工具的 LLM）、接地（座標輸出）、長時程記憶，以及評測。

**類型：** 總結專案
**程式語言：** Python (stdlib, action schema + agent loop skeleton)
**先修單元：** 階段 12 · 05（LLaVA）、階段 12 · 09（Qwen-VL JSON）、階段 14（代理程式工程）
**時間：** 約 240 分鐘

## 學習目標

- 設計一個多模態代理程式迴圈：感知 → 推理 → 動作 → 觀察 → 重複。
- 做一份 VLM 能以 JSON 吐出的 GUI 接地輸出 schema（點擊座標、輸入文字、捲動、拖曳）。
- 比較純截圖代理程式、無障礙樹代理程式與混合式代理程式。
- 在 VisualWebArena 的一小塊切片上，架起一次多模態代理程式的基準評測。

## 問題所在

一段訂票網站的工作流程：「幫我找 4 月 15 日飛東京的班機，走道座位、800 美元以下，然後訂下去。」

一個多模態代理程式得要：

1. 對瀏覽器截圖。
2. 把截圖 + URL + 目標解析成一份計畫。
3. 吐出一個結構化動作：點擊 (x,y)、在元素 E 輸入「Tokyo」、向下捲動、選取（單選鈕）。
4. 把那個動作施加到瀏覽器上。
5. 觀察新狀態（下一張截圖）。
6. 重複，直到任務完成。

每一步都是一次多模態 VLM 呼叫。VLM 的輸出必須是可解析的 JSON。錯誤會跨步驟累積，所以復原能力很要緊。

## 核心概念

### GUI 接地 —— 那個基本單位

GUI 接地就是：給定一張截圖與一段自然語言指令，輸出該點擊的 (x, y) 座標（或其他動作）。

SeeClick（arXiv:2401.10935）是第一個規模化的開放成果：在合成 + 真實的 GUI 資料上微調一個 VLM，把座標當成純文字詞元輸出。有效。

CogAgent（arXiv:2312.08914）為密集的 UI 加上了 1120x1120 的高解析度編碼。分數：網頁導覽約 84%。

Ferret-UI（arXiv:2404.05719）聚焦行動裝置 UI，並整合了 iOS 的無障礙資料。

輸出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

那個 `element_desc` 有助於復原：如果座標在不同截圖之間跑掉了，這個語意提示能讓系統重新接地。

### 動作 schema

一份典型的動作 schema 有 6 到 10 種動作型別：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

代理程式每一步吐出一個動作。瀏覽器包裝層執行它，並回傳新狀態。

### 純截圖對無障礙樹

有兩種輸入模式：

- 純截圖：完整影像，沒有結構資訊。最通用；在任何應用程式上都能運作。
- 無障礙樹：結構化的 DOM／iOS 無障礙資訊。做接地可靠得多；但只在有這棵樹的地方可用。
- 混合：兩者兼用，把樹當成原子動作的可靠接地器，把截圖當成語意脈絡。

生產級代理程式在可行時都用混合式。瀏覽器自動化（Selenium + 無障礙介面）一定有那棵樹；桌面應用程式則有時候有。

### 長時程記憶

一段 20 步的工作流程會產生 20 張截圖。VLM 的脈絡很快就滿了。有三種壓縮策略：

- 摘要鏈：每 5 步就把發生過的事摘要一次，丟掉舊截圖。
- 跳格：只留第一張、最後一張，以及每隔 3 張留一張。
- 工具記錄的日誌：執行動作，把做過什麼記成文字日誌；不再回頭看舊截圖。

Claude 的電腦操作 API 用的是日誌這套模式。更簡單，也更可靠。

### 視覺工具使用

ChartAgent（arXiv:2510.04514）為圖表理解引入了視覺工具使用：裁切、縮放、OCR、呼叫外部偵測。代理程式可以把「裁切到區域 (100, 200, 300, 400) 然後呼叫 OCR」當成一次工具呼叫輸出。工具回傳文字；VLM 繼續推理。

這套模式可以類推：set-of-mark 提示、區域標註與外部偵測工具，全都符合同一套「吐出一次工具呼叫、收到一份結構化回應」的 schema。

### 2026 年的基準

- ScreenSpot-Pro。在約 1000 張網頁截圖上做 GUI 接地。開放 SOTA 的 Qwen2.5-VL-72B 約 85%。前沿約 90%。
- VisualWebArena。端到端的網頁任務（購物、論壇、分類廣告）。開放 SOTA 約 20%。Gemini 3 Pro 約 27%。
- AgentVista（arXiv:2602.23166）。2026 年最難的基準。橫跨 12 個領域的真實工作流程。前沿模型 27% 到 40%；開放模型 10% 到 20%。
- WebArena／WebShop。較舊的基準；已被前沿模型飽和。

### 為什麼它依然困難

代理程式表現的瓶頸：

1. 細尺度上的視覺接地。「點那個小小的 X」在行動裝置解析度下常常失敗。
2. 長時程規劃。做完 10 個動作後，代理程式就從目標漂走了。
3. 錯誤復原。當一次點擊失敗（按錯按鈕）時，要偵測並復原，這在訓練資料裡幾乎沒有。
4. 跨頁脈絡。在分頁之間跳轉，或碰上長表單，狀態就流失了。

研究方向：記憶架構、明確的重新規劃、多模態驗證（用截圖比對來確認動作是否成功）。

### 這個總結專案要動手做什麼

總結任務：做一個電腦操作代理程式，它要：

1. 讀取一個訂票網站模擬頁面的 HTML + 截圖。
2. 規劃一段多步驟序列：搜尋 → 選取 → 填表 → 送出。
3. 吐出符合那份動作 schema 的 JSON 動作。
4. 在一份固定的 10 題切片上評測。

這一課提供了鷹架程式碼，很容易擴充成一個真正的瀏覽器。

## 框架應用

`code/main.py` 就是那份總結專案的鷹架：

- 動作 schema 的 JSON 定義（10 種動作）。
- 以 dict 表示的模擬瀏覽器狀態。
- 代理程式迴圈骨架：接收狀態、吐出動作、施加、循環。
- 一份 10 題的迷你基準（合成頁面），用來量測端到端成功率。
- 一個在動作失敗時觸發的錯誤復原掛鉤。

## 產出交付

這一課產出 `outputs/skill-multimodal-agent-designer.md`。給定一項電腦操作產品（領域、動作集、評測目標），它會設計出完整的代理程式迴圈、記憶策略、接地模式與預期的基準分數。

## 練習

1. 用一個 `screenshot_region` 工具（裁切 + 縮放）擴充那份動作 schema。哪些任務會因此受益？

2. 讀 AgentVista（arXiv:2602.23166）。描述最困難的那類任務，以及前沿模型為什麼仍然失敗。

3. 長時程記憶壓縮：設計一條摘要鏈，最多只保留 4 張截圖為活躍狀態，日誌則不限筆數。

4. 做一個錯誤復原掛鉤：動作失敗時（找不到按鈕），代理程式下一步該做什麼？

5. 在 10 項網頁任務上，比較純截圖的 Claude 4.7 與「截圖 + 無障礙樹」混合式的 Qwen2.5-VL。哪一個在哪些任務上勝出？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| GUI 接地 | 「點擊座標」 | 模型針對截圖上某段指令的目標，輸出 (x,y) |
| 動作 schema | 「工具定義」 | 以 JSON 描述的合法動作（點擊、輸入、捲動、拖曳） |
| 無障礙樹 | 「結構化 DOM」 | 來自瀏覽器／iOS API、機器可讀的 UI 階層 |
| 混合式代理程式 | 「截圖 + 樹」 | 同時使用影像與結構資訊；比單用任一種都可靠 |
| 視覺工具使用 | 「縮放／裁切／偵測」 | 代理程式在計畫執行中途呼叫外部視覺工具（OCR、偵測） |
| 摘要鏈 | 「記憶壓縮」 | 用週期性的文字摘要取代冗長的截圖歷史 |
| VisualWebArena | 「端到端網頁基準」 | 2024 年的端到端網頁任務基準 |
| AgentVista | 「2026 年的困難基準」 | 橫跨 12 個領域的真實工作流程；連 Gemini 3 Pro 都只有約 30% |
