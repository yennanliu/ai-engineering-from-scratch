# 行動預算、迭代上限與成本治理器

> 某家中型電商的代理，在團隊啟用「訂單追蹤」技能之後，每月 LLM 成本從 1,200 美元跳到 4,800 美元。那不是計價的臭蟲。那是一個代理找到了一個新迴圈，並在裡面持續花錢。Microsoft 的 Agent Governance Toolkit（2026 年 4 月 2 日）把針對這一類的防禦編纂了下來：逐請求的 `max_tokens`、逐任務的詞元與金額預算、逐日／逐月上限、迭代上限、分層模型路由、提示詞快取、脈絡開窗、對昂貴行動的 HITL 檢查點、預算破表時的斷路開關。Anthropic 的 Claude Code Agent SDK 以不同名稱出貨同一批原語。財務速度限制 —— 例如 10 分鐘內超過 50 美元就切斷存取 —— 比每月上限更快抓到迴圈。

**類型：** 學習
**程式語言：** Python (stdlib, layered cost-governor simulator)
**先修單元：** 階段 15 · 10（權限模式）、階段 15 · 12（持久執行）
**時間：** 約 60 分鐘

## 問題所在

自主代理每一輪都在花真的錢。聊天機器人的壞輸出是一則壞回覆；代理的壞迴圈是一張帳單。業界對這個失敗模式有記錄的稱呼是「Denial of Wallet」（錢包阻斷）—— 代理一直推理、一直呼叫工具、一直計費，而沒有東西阻止它，因為沒有東西是為此而設計的。

修法不是一個數字。它是一疊處在不同時間尺度與粒度上的限制：逐請求、逐任務、逐小時、逐日、逐月。一疊設計良好的限制，能在幾分鐘內抓到失控迴圈、在幾小時內抓到緩慢滲漏、在一天內抓到糟糕的版本。當代理是長時程且自主時，同一疊限制也是「還有預算存在」這件事本身的保障。

這是一堂工程課：數學很簡單，紀律才是團隊失敗的地方。下面這份限制清單，全都出現在 Microsoft 的 Agent Governance Toolkit 或 Anthropic 的 Claude Code Agent SDK 文件中。

## 核心概念

### 成本治理器的堆疊

1. **逐請求的 `max_tokens`。** 簡單。防止任何一次呼叫吐出無界的補全。
2. **逐任務的詞元預算。** 整趟執行加起來不得超過 N 個詞元。到上限就硬停。
3. **逐任務的金額預算。** 跟詞元一樣，但以貨幣計。Claude Code 裡的 `max_budget_usd`。
4. **逐工具的呼叫上限。** `WebFetch` 呼叫不得超過 N 次、`shell_exec` 不得超過 N 次，等等。
5. **迭代上限（`max_turns`）。** 代理迴圈的總迭代次數；防止無窮推理迴圈。
6. **逐分鐘／逐小時／逐日／逐月上限。** 滾動視窗。在不同時間尺度上抓滲漏。
7. **財務速度限制。** 例如「若 10 分鐘內花費超過 50 美元，就切斷存取」。在每月上限觸發之前，就抓到基於迴圈的燒錢。
8. **分層模型路由。** 預設走較小的模型；只有在分類器判斷該任務值得時，才升到較大的模型。
9. **提示詞快取。** 系統提示詞與穩定脈絡存在供應商的快取裡；重送的詞元成本趨近於零。
10. **脈絡開窗。** 用壓實／摘要把活躍脈絡壓在門檻以下；直接降低詞元成本。
11. **對昂貴行動的 HITL 檢查點。** 在已知昂貴的行動（長工具呼叫、大量下載、升級到昂貴模型）之前，要求人按一下。
12. **預算破表時的斷路開關。** 任何上限觸發，工作階段就中止。上限被記錄下來；重新啟用要走另一條路徑。

### 為什麼要一疊，而不是一個上限

單一個每月上限，要等到錢包空了才抓得到失控代理。單一個逐請求上限，在工作階段層級什麼都抓不到。不同的失敗模式需要不同的時間尺度：

- **失控迴圈**（代理卡在 5 秒一次的重試裡）：被速度限制抓到。
- **緩慢滲漏**（代理每項任務做了約 2 倍於預期的工作）：被每日上限抓到。
- **糟糕的版本**（新版用掉 5 倍詞元）：被每週／每月上限抓到。
- **正常的暴衝**（真實需求，不是臭蟲）：被每小時／每日上限抓到，並留下清楚的日誌。

### 一個執行環境的預算表面

Claude Code Agent SDK 暴露（公開文件）：

- `max_turns` —— 迭代上限。
- `max_budget_usd` —— 金額上限；破表時工作階段中止。
- `allowed_tools`／`disallowed_tools` —— 工具允許清單與拒絕清單。
- 工具使用前的掛鉤點，供自訂的成本記帳使用。

要跟權限模式階梯（第 10 課）結合起來用。一個沒有 `max_budget_usd` 的 `autoMode` 工作階段，就是未受治理的自主性。Anthropic 明確把 Auto Mode 定位成需要搭配預算控制；那個分類器與成本是正交的。

### 歐盟 AI 法案、OWASP Agentic Top 10

Microsoft 的 Agent Governance Toolkit 涵蓋 OWASP Agentic Top 10 與歐盟 AI 法案第 14 條（人類監督）的要求。要在歐盟做生產部署，日誌與上限的強制執行都不是選配。

### 那個被觀察到的 1,200 → 4,800 美元案例

Microsoft 文件裡那個真實案例：一家電商的代理在加了一項新工具之後，每月成本變成三倍。那項工具讓代理在每個工作階段都去輪詢訂單狀態。沒有迴圈偵測。沒有逐工具上限。沒有對週對週成長的警示。修法是加上逐工具上限，外加一個每日成長警示。這是一份樣板：每一個新工具表面都是一個新的潛在迴圈；每一個新工具都需要它自己的上限與它自己的警示。

## 框架應用

`code/main.py` 模擬一趟代理執行，分別在有與沒有分層成本治理器堆疊的情況下跑。被模擬的代理在若干輪之後漂進一個輪詢迴圈；分層堆疊在速度視窗內就抓到它，而單一個每月上限要好幾天後才會觸發。

## 產出交付

`outputs/skill-agent-budget-audit.md` 稽核一次被提議的代理部署的成本治理器堆疊，並標出缺少的層。

## 練習

1. 跑 `code/main.py`。確認在輪詢迴圈的軌跡上，速度限制比迭代上限先觸發。接著停用速度限制，量在迭代上限抓到它之前，代理「花掉」多少。

2. 替一個瀏覽器代理（第 11 課）設計一組逐工具上限。哪項工具需要最緊的上限？哪項工具可以無界執行而沒有風險？

3. 讀 Microsoft Agent Governance Toolkit 的文件。列出該工具組點名的每一種上限型別。把每一種對映到某個失敗模式（失控迴圈、緩慢滲漏、糟糕版本、暴衝）。

4. 替一項實際的任務（例如「檢傷分類一個儲存庫裡的 50 個 issue」）估算隔夜無人看管執行的價格。把 `max_budget_usd` 設在你點估計的 2 倍。替那個 2 倍辯護。

5. Claude Code 的 `max_budget_usd` 是以工作階段的總成本觸發。設計一項你會在外部強制執行的互補速度限制。什麼觸發那次切斷，而重新啟用長什麼樣子？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|---|---|---|
| 錢包阻斷 | 「失控的帳單」 | 代理迴圈不斷產生花費，卻沒有上限能停下它 |
| max_tokens | 「逐請求上限」 | 單一次補全大小的天花板 |
| max_turns | 「迭代上限」 | 一個工作階段中代理迴圈迭代次數的天花板 |
| max_budget_usd | 「金額斷路開關」 | 工作階段的成本上限；破表就中止 |
| 速度限制 | 「速率上限」 | 對短視窗內花費的限制（例如 10 分鐘 50 美元） |
| 分層路由 | 「小模型先上」 | 預設用便宜模型；只有分類器認為值得時才升級 |
| 提示詞快取 | 「被快取的系統提示詞」 | 供應商端的快取把重送的詞元成本降到趨近於零 |
| HITL 檢查點 | 「人工核准閘門」 | 昂貴行動之前需要人按一下 |
