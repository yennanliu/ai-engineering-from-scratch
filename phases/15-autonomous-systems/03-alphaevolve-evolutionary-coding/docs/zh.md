# AlphaEvolve —— 演化式寫程式代理

> 把一個前沿寫程式模型跟一個演化迴圈、外加一個機器可檢核的評估器配起來。讓迴圈跑得夠久。它會發現一套只用 48 次純量乘法的 4x4 複數矩陣乘法程序 —— 56 年來第一次勝過 Strassen。它還找到一項 Google 全公司規模的 Borg 排程啟發式，在生產環境中收回約 0.7% 的叢集運算量。這個架構刻意做得無聊。收穫來自評估器的嚴謹。

**類型：** 學習
**程式語言：** Python (stdlib, evolutionary-loop toy)
**先修單元：** 階段 15 · 01（長時程的框架）、階段 15 · 02（自學式推理）
**時間：** 約 60 分鐘

## 問題所在

大型語言模型會寫程式。演化演算法會在程式碼上搜尋。兩者各自被試了幾十年；兩者都撞到天花板。LLM 的天花板是虛構：模型寫出看起來合理、但做的並不是它宣稱那件事的程式碼。演化的天花板是搜尋成本：在語法上做隨機突變，很少能產出編譯得過的程式，更別說更好的程式。

AlphaEvolve（Novikov 等人，DeepMind，arXiv:2506.13131，2025 年 6 月）把兩者結合起來。LLM 對一個程式資料庫提出有針對性的編輯；自動評估器替每個變體評分；高分變體成為未來世代的親代。LLM 負責「寫出看似合理的程式碼」這個昂貴步驟；評估器負責抓出那些虛構。這個迴圈會跑上數小時到數週。

回報的結果：48 次純量乘法的 4x4 複數矩陣乘法（Strassen 1969 年的界是 49）、一項用在 Google 生產環境的 Borg 排程啟發式、FlashAttention 核心加速 32.5%、Gemini 訓練吞吐量的改進。

這個架構之所以行得通，是因為評估器是機器可檢核的。在評估器不是那樣的地方，它就行不通。那份不對稱，就是這一課的重點。

## 核心概念

### 那個迴圈

1. 從一支正確但次佳的種子程式 `P_0` 開始。
2. 維護一個變體程式資料庫，每支都由評估器評分。
3. 從資料庫中取樣一個或多個親代（MAP-elites 式或島嶼式）。
4. 提示 LLM（大量候選用 Gemini Flash，困難的用 Gemini Pro）產出親代的修改版變體。
5. 編譯、執行，並用保留的評估器評測該變體。
6. 依其分數與特徵向量為鍵插入資料庫。
7. 重複。

有兩個細節要緊。第一，提示給 LLM 的不只是親代程式 —— 通常還包含資料庫裡幾支頂尖變體、評估器的簽章，以及一段簡短的任務描述。模型的職責是提出一項可能提升分數的針對性改動。第二，資料庫是有結構的（MAP-elites 網格、島嶼式），好讓迴圈探索多樣性，而不只是追著當前領先者跑。

### 為什麼評估器不容妥協

AlphaEvolve 的每一項斬獲，都來自那些評估器又快、又決定性、又難以被操弄的領域：

- **矩陣乘法演算法**：一個把矩陣相乘並逐位元檢查相等的單元測試。
- **Borg 排程啟發式**：一個生產等級的模擬器，重播歷史叢集負載並量測浪費掉的運算量。
- **FlashAttention 核心**：一個正確性測試，加上在真實硬體上的牆鐘基準。
- **Gemini 訓練吞吐量**：量到的每步 GPU 秒數。

在每個案例中，評估器都抓住了那類原本會主導一切的 LLM 錯誤：虛構的正確性宣稱、在硬體上就蒸發的效能宣稱，以及邊界情況的失敗。把評估器拿掉，這個迴圈就會朝「漂亮的程式碼」最佳化。

### 獎勵入侵是同一句話的另一面

演化會朝評估器所量測的任何東西最佳化。若評估器不完美，這個迴圈就會找到那個不完美之處。在一個未經驗證的領域裡，迴圈會朝表面特徵最佳化，而不是朝預期行為。DeepMind 在論文中明白標示了這點：AlphaEvolve 的成功，只會轉移到那些「評估器的嚴謹度配得上搜尋野心」的領域。

2025-2026 年程式碼搜尋迴圈中獎勵入侵的具體例子：

- 獎勵「完成時間」的最佳化目標，結果獎勵了送出空解答。
- 獎勵「測試下的正確性」的基準分數，結果獎勵了背測試與過擬合。
- 一個「程式碼品質」的代理指標，結果獎勵了刪註解與改變數名，語意毫無變化。

AlphaEvolve 的修法：出貨一個 LLM 從未見過的保留評估器，其輸入在評測當下才產生。就算如此，DeepMind 仍建議對任何被提議的部署都做強力審查。

### 為什麼 LLM + 搜尋勝過任一者單獨使用

LLM 能產出編譯得過、語意上合理的修改。在一份 2000 行的 Python 檔上做隨機突變的遺傳演算法，幾乎總是產出語法錯誤。LLM 也把搜尋集中在合理的鄰域裡（改一個函數，而不是改隨機位元組），這大幅減少浪費掉的評估器呼叫。

反過來，評估器抓住 LLM 的虛構。LLM 會很有自信地宣稱某個函數「在極限下是 O(n log n)」，而它其實是 O(n^2)；一個牆鐘基準讓這個問題塵埃落定。

### AlphaEvolve 在前沿堆疊裡的位置

| 系統 | 產生器 | 評估器 | 領域 | 代表斬獲 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正確性 + 基準 | 演算法、核心、排程器 | 48 乘法的 4x4 矩陣乘法 |
| FunSearch（DeepMind，2023） | PaLM / Codey | 正確性 | 組合數學 | cap-set 下界 |
| AI Scientist v2（Sakana，第 5 課） | GPT/Claude | LLM 批評 + 實驗 | ML 研究 | ICLR 工作坊論文 |
| Darwin Godel Machine（第 4 課） | 代理鷹架 | SWE-bench / Polyglot | 代理程式碼 | SWE-bench 20% → 50% |

四者都是同一份食譜的變體：產生器加評估器，迴圈。差別在於評估器批改什麼，以及它有多嚴謹。

## 框架應用

`code/main.py` 在一個玩具符號迴歸問題上實作一個最小的類 AlphaEvolve 迴圈。那個「LLM」是一個 stdlib 的替身，會對一支計算目標函數的程式提出細小的語法突變。那個「評估器」在保留的測試點上量均方誤差。

觀察：

- 最佳分數如何隨世代改善。
- MAP-elites 網格如何讓多樣的解活著，好讓迴圈不會收斂到局部極小值。
- 拿掉保留測試（只用訓練資料的評估器）之後，迴圈如何壯觀地過擬合。

## 練習

1. 跑 `code/main.py`。記下最佳分數的軌跡。停用保留評估器（旗標 `--no-holdout`）再跑一次。把過擬合量化。

2. 讀 AlphaEvolve 論文第 3 節談 MAP-elites 網格的部分。替一個新問題（例如編譯器最佳化 pass）設計一個特徵向量描述子，讓搜尋維持多樣。

3. 那個 48 次乘法的 4x4 結果，在 56 年後改進了 Strassen 的 49 乘法界。讀論文附錄 F，用三句話解釋為何這個問題的評估器特別容易做對，以及為何多數領域並非如此。

4. 提出一個 AlphaEvolve 會失敗的領域。精確指出評估器在哪裡壞掉，以及為什麼。

5. 針對一個你熟悉的領域，寫出你會使用的評估器簽章。包含 (a) 正確性條件、(b) 效能指標、(c) 保留輸入的產生規則、(d) 至少一項反獎勵入侵的檢查。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|---|---|---|
| AlphaEvolve | 「DeepMind 那個演化式寫程式代理」 | Gemini + 程式資料庫 + 機器可檢核的評估器 |
| MAP-elites | 「保存多樣性的檔案庫」 | 以特徵向量為鍵的網格；每一格放著具該描述子的最佳變體 |
| 島嶼模型 | 「平行演化的子族群」 | 獨立族群，定期遷徙；防止過早收斂 |
| 機器可檢核的評估器 | 「決定性的神諭」 | LLM 造不了假的單元測試、模擬器或基準 —— 這個迴圈的前置條件 |
| 獎勵入侵 | 「最佳化那個量測，不是那個目標」 | 迴圈找到一條不用做預期任務就能把分數最大化的路 |
| 種子程式 | 「起點」 | 迴圈據以演化的初始「正確但次佳」程式 |
| 保留評估器 | 「LLM 從未見過的評測資料」 | 在評測當下才產生的輸入，用來防止背答案 |
