# AI Scientist v2 —— 工作坊等級的自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）跑完整條研究迴圈：假說、程式碼、實驗、圖表、撰寫、投稿。它是第一個讓自動產生的論文通過 ICLR 2025 工作坊同儕審查的系統。獨立評估（Beel 等人）發現有 42% 的實驗因程式錯誤而失敗，而文獻回顧經常把既有概念誤標成新穎。Sakana 自己的文件警告，這份程式庫會執行 LLM 寫的程式碼，並建議用 Docker 隔離。這幅圖的兩半，都是重點。

**類型：** 學習
**程式語言：** Python (stdlib, research-loop state-machine toy)
**先修單元：** 階段 15 · 03（AlphaEvolve）、階段 15 · 04（DGM）
**時間：** 約 60 分鐘

## 問題所在

研究是一項開放式任務。不像 AlphaEvolve 的演算法搜尋或 DGM 那種受基準界定的自我修改，一項研究成果沒有機器可檢核的正確性判準。論文是由審稿人評判的，不是由單元測試。這讓迴圈更難收攏 —— 而一旦收攏也更有價值，因為研究正是複利式進展所在之處。

AI Scientist v1（Sakana，2024）藉由從人類撰寫的樣板出發來收攏迴圈。LLM 在固定鷹架內把實驗填進去。AI Scientist v2（Yamada 等人，2025）則以「代理式樹搜尋加視覺語言模型批評迴圈」拿掉了樣板這項要求。這個系統產生構想、實作實驗、產出圖表、撰寫論文，並依審稿回饋迭代。

同儕審查的裁決：一篇 v2 產生的論文在 ICLR 2025 工作坊被接受（有揭露）。獨立評估的裁決：這個系統遠遠稱不上可靠。兩者都是真的。

## 核心概念

### 那個架構

1. **構想產生。** LLM 以一個主題與先前文獻為條件提出研究構想。v1 用樣板；v2 則在假說空間上做代理式搜尋。
2. **新穎性檢查。** 一個文獻檢索步驟去檢查這個構想是否已被發表。Beel 等人的評估發現誤標就發生在這一步 —— 既有方法常被分類為新穎。
3. **實驗計畫。** 代理草擬實驗協定並寫程式碼。
4. **執行。** 程式碼在沙箱中執行。失敗會被餵回一個重試迴圈。在 Beel 等人的量測中，這一階段有 42% 的實驗因程式錯誤而失敗。
5. **圖表產生。** 一個視覺語言模型讀產出的圖表，並為了清晰而重寫它們。這是 v2 的關鍵技術新增。
6. **撰寫。** LLM 草擬論文，並與一個內部審稿人迭代。
7. **選配：投稿。** 論文被投到某個場次。

### 那項工作坊接受的結果代表什麼

一篇 v2 產生的論文通過了 ICLR 2025 某工作坊的同儕審查。作者向議程委員會揭露了該論文的出處。這次接受是一個資料點；它不是宣稱這個系統「會做研究」的許可證。

重要的脈絡：工作坊論文的門檻低於主會議論文。同儕審查是有雜訊的；任何一天都只有一小部分投稿會被接受。一次成功是概念驗證，不是可靠度宣稱。2026 年那篇 Nature 論文記錄了端到端的迴圈，而它本身是由人類研究者共同署名的；那不是「這個系統寫了一篇 Nature 論文」。

### 獨立評估發現了什麼

Beel 等人（arXiv:2502.14297）做了一次外部評估。頭條發現：

- **實驗失敗。** 42% 的實驗因程式錯誤（錯誤的 import、形狀不匹配、未定義變數）而失敗。重試迴圈接住了一些，但不是全部。
- **新穎性誤標。** 文獻檢索那一步經常把既有概念標成新穎。這是研究版的幻覺。
- **呈現品質落差。** 視覺語言模型的圖表批評產出了可發表等級的視覺呈現，掩蓋了底下的實驗弱點。

最後一項發現對本階段最重要。一個能產出令人信服的輸出、卻沒有做出令人信服的研究的系統，比一個明顯失敗的系統更危險，而不是更安全。評測必須觸及底層的那些主張，不能停在圖表上。

### 沙箱逃逸的顧慮

Sakana 自己的儲存庫 README 警告：

> 由於本軟體的性質 —— 它會執行 LLM 產生的程式碼 —— 我們無法保證安全。存在危險套件、不受控的網路存取，以及生出非預期行程的風險。使用風險自負，並請考慮 Docker 隔離。

這就是在未經驗證領域中，自主性的運維形狀。LLM 寫程式碼；程式碼執行；程式碼可以做任何那個行程被允許做的事。若沒有一個硬性限制檔案系統、網路與行程行為的沙箱，任何自我導向的研究代理都可以外洩資料、燒掉運算量，或改寫自己。

AlphaEvolve 的沙箱故事比較容易，因為它的評估器很緊。AI Scientist v2 的迴圈則以開放式目標執行開放式程式碼。這就是它為何需要更強的隔離（Docker 是底線；seccomp／gVisor 更好），以及在任何投稿離開系統之前都要有人工審查。

### v2 在前沿堆疊裡的位置

| 系統 | 對象 | 輸出種類 | 評估器 | 已知失敗 |
|---|---|---|---|---|
| AlphaEvolve | 演算法 | 程式碼 | 單元測試 + 基準 | 受評估器嚴謹度所限 |
| DGM | 代理鷹架 | 程式碼 | SWE-bench | 獎勵入侵 |
| AI Scientist v2 | 研究論文 | 文字 + 程式碼 + 圖表 | 同儕審查（弱） | 實驗失敗、誤標、拋光掩蓋弱點 |

三者之中，v2 的自動評估器最弱、輸出表面最寬，而通往公開產物的路徑最短。安全工作大半是由那些運維控制（沙箱、審查、揭露）在扛。

## 框架應用

`code/main.py` 把 v2 的迴圈模擬成一台狀態機：構想 → 新穎性檢查 → 實驗 → 圖表 → 撰寫 → 審查 → 接受或迭代。每個狀態都有一個可設定的失敗機率，取自 Beel 等人的發現。把模擬器跑 N 個迴圈並數：

- 有多少構想抵達投稿。
- 有多少投稿帶著一項被拋光論文掩蓋掉的關鍵實驗瑕疵。
- 重試預算如何在品質與產出量之間做取捨。

## 產出交付

`outputs/skill-ai-scientist-sandbox-review.md` 是一份兩道閘門的審查檢查清單，適用於任何由研究迴圈代理產出、且即將離開沙箱的東西。

## 練習

1. 用預設參數跑 `code/main.py`。有多少比例的迴圈執行產出「乾淨」的論文？有多少比例產出的論文帶著被圖表批評拋光掉的實驗失敗瑕疵？

2. 預設值已經用了 Beel 等人的 42% / 25%。改用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 再跑一次，然後用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 再跑一次。「拋光但有瑕疵」的占比在兩趟之間怎麼移動？

3. 讀 Sakana AI Scientist v2 儲存庫 README 關於沙箱需求的部分。針對一趟多天的自主執行，說出你會額外施加的兩項限制（Docker 之外）。

4. 讀 Beel 等人第 4 節談呈現品質落差的部分。設計一項額外的評估器，能抓到看起來拋光、實驗卻有瑕疵的論文。

5. 為研究代理的產出提出一套人工審查協定，讓它比「一位博士讀每一篇論文」更能擴展。指認出瓶頸，並圍繞它做設計。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|---|---|---|
| AI Scientist v1 | 「Sakana 那個樣板化的研究代理」 | 把實驗填進一個固定鷹架裡 |
| AI Scientist v2 | 「免樣板的研究代理」 | 代理式樹搜尋，配上 VLM 的圖表批評 |
| 代理式樹搜尋 | 「會分岔的研究代理」 | 平行展開多份實驗計畫；由內部批評者剪枝 |
| 視覺語言批評 | 「VLM 替圖表拋光」 | 多模態模型讀圖表，並為了清晰重寫它們 |
| 文獻檢索 | 「新穎性檢查」 | 搜尋既有工作以確認構想新穎 —— 已被記錄會誤標 |
| 拋光掩蓋 | 「論文漂亮、研究破洞」 | 呈現品質超過實驗品質；把弱點藏起來 |
| 沙箱逃逸 | 「LLM 的程式碼衝出去了」 | 代理執行的程式碼做了迴圈設計者沒打算讓它做的事 |
